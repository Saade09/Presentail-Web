OBJECTIVE

Redesign and implement the Presentail individual blog article template so every article feels like a premium editorial extension of the storefront, is easier to read and scan, supports organic-search intent, and provides a tasteful path from editorial content to shopping.

This task is specifically for individual article pages. It is separate from the blog landing-page redesign task:
Redesign and implement the Presentail blog landing page

REFERENCE PAGE

Use this existing article as the primary implementation and QA example:
https://presentail.com/en/blog/send-roses-to-lebanon

Use the approved article redesign concept from the August 13 design review as the visual direction. Recreate the design with production components and real CMS content; do not embed the mockup as an image.

PRIMARY UX PROBLEM

The existing article template gives most of the first viewport to the hero photograph and pushes the title below the fold. Visitors cannot immediately identify the article, evaluate its relevance, or take the intended action. The redesign must place the editorial proposition first, reduce image dominance, improve long-form readability, and integrate commerce without turning the article into a product-listing page.

DESIRED ABOVE-THE-FOLD ORDER

1. Utility bar and standard Presentail header
2. Compact breadcrumb
3. Category / geography label
4. Article H1
5. Short article introduction/dek
6. Updated date and estimated reading time
7. Primary article-specific CTA and share action
8. Restrained editorial hero image
9. Beginning of article body visible as early as reasonably possible

HEADER AND GLOBAL NAVIGATION

- Preserve the existing Presentail utility bar, country/city selector, language selector, primary navigation, centered wordmark, search, account, and cart behavior.
- Align dimensions, spacing, icons, dividers, hover states, and mobile behavior with the current storefront header.
- Do not create a blog-specific header variant unless required by the existing architecture.
- Confirm the header remains functional at all target breakpoints and does not obscure article content.

BREADCRUMB AND ARTICLE INTRO

- Replace the long, repetitive breadcrumb treatment with a compact hierarchy such as:
  Journal / Gifting Guides / Lebanon
- Remove the separate “Back to the Journal” link from the intro area if the breadcrumb already provides that route.
- Render a small uppercase taxonomy label above the H1, for example:
  LEBANON · GIFTING GUIDE
- Place the H1 before the hero image.
- For the sample article, the preferred display H1 is:
  How to Send Roses to Lebanon
- Use the dek to carry supporting search language, for example:
  Same-day delivery, nationwide availability, and how to choose an arrangement they’ll love.
- Show:
  - Last updated or publication date
  - Estimated reading time
  - Optional author only if the author identity is real and maintained
- Use one H1 only.
- Keep the H1 width controlled so it does not create awkward line breaks at common desktop widths.

PRIMARY CTA AND SHARE ACTION

- Add a contextually relevant CTA near the article intro.
- For the sample article:
  Shop roses in Lebanon
- CTA styling should use Presentail’s dark petrol-teal primary treatment.
- CTA destination must respect the current market/city and language context.
- Include an understated Share action beside or near the CTA.
- Share should use the Web Share API where supported, with a copy-link fallback.
- Add accessible labels and visible keyboard focus states.
- Track CTA clicks and share actions through the existing analytics implementation.

HERO IMAGE

- Move the hero below the title, dek, metadata, and CTA.
- Use a restrained wide editorial crop rather than a very tall product-banner crop.
- Target approximately 16:9 or a similarly wide ratio, with an appropriate desktop maximum height around 480–560 px.
- Keep image dimensions explicit to prevent layout shift.
- Use responsive image sources and appropriate modern formats.
- Use eager/high-priority loading only when the hero qualifies as the LCP image.
- All article hero images must come from Presentail-owned or approved content.
- Replace the current sample image because “Blooming Beirut” branding is visibly embedded in it and conflicts with the Presentail brand.
- Ensure the replacement image contains no third-party logo, wordmark, packaging mark, or watermark.
- Add meaningful alt text from a CMS field, with a sensible fallback.
- Preserve subject framing on mobile with controlled object-position behavior.

PAGE BACKGROUND, COLOR, AND TYPOGRAPHY

- Use a warm ivory/off-white article background rather than a stark white canvas.
- Use deep petrol teal for primary controls, links, active navigation, and restrained accents.
- Use charcoal for body text and a muted but accessible gray for metadata.
- Use the existing editorial serif for the H1, H2s, pull quotes, and feature headings.
- Use the existing sans serif for navigation, breadcrumbs, body text, metadata, buttons, and labels.
- Target article body text around 18–20 px on desktop with approximately 1.6–1.7 line height.
- Maintain WCAG AA contrast for all text and controls.

ARTICLE READING LAYOUT

- Limit the primary prose column to approximately 680–740 px on desktop.
- Do not allow body paragraphs to span the full hero-image width.
- Use a responsive editorial grid that can support:
  - Slim table of contents
  - Main article column
  - Optional secondary commerce or utility card
- On tablet and mobile, collapse to one main content column.
- Avoid excessive empty margins while preserving a calm, premium rhythm.
- Add generous but consistent spacing before and after H2/H3 sections.
- Style lists, links, blockquotes, tables, captions, and inline images consistently.
- Prevent widows/orphans where practical and avoid isolated headings at viewport/page boundaries.

TABLE OF CONTENTS

- Add an optional “IN THIS GUIDE” table of contents for sufficiently long articles.
- Generate links from article H2s or explicit CMS anchors.
- Make links scroll to the correct section without hiding headings behind the sticky header.
- Highlight the current section only if this can be implemented without adding significant complexity or JavaScript weight.
- On mobile, render the table of contents as a compact disclosure/accordion near the beginning of the article.
- Do not show it for short articles with too few sections.

REUSABLE EDITORIAL COMPONENTS

Support and style these reusable article blocks:

- H2 and H3 sections
- Bulleted and numbered lists
- Inline editorial images with captions
- Pull quote
- Information callout
- Delivery/service callout
- FAQ accordion
- Related-article cards
- Optional product/collection recommendation
- Final editorial CTA
- Source/reference links where appropriate

For the sample article, include a service callout near the relevant content:
- Title: Same-day delivery
- Short supporting copy using the live cutoff/coverage logic where available
- Small delivery icon
- Quiet sage/ivory treatment; do not style it like a promotional banner

COMMERCE INTEGRATION

- Add a reusable, optional product or collection recommendation component.
- It may appear beside the article on wide screens or inline at a natural break.
- For the sample article, use:
  View rose arrangements →
- Keep the module visually secondary to the editorial content.
- Show no more than one compact recommendation in the first article section.
- Avoid dense product grids, intrusive sticky popups, auto-rotating carousels, or repeated CTA banners.
- Preserve the user’s selected city/market, locale, currency, and availability context.
- If product data is unavailable, hide the component cleanly rather than showing an empty state.
- Track recommendation impressions and clicks using the existing analytics standard.

ARTICLE CONTENT STRUCTURE FOR THE SAMPLE PAGE

Ensure the template supports a clear structure similar to:

- Sending roses to Lebanon
- Delivery areas
- Same-day delivery and order cutoffs
- Choosing the right rose arrangement
- Prices and payment options
- Frequently asked questions
- Related guides

The task is to build the reusable template and components, not rewrite the entire article. However, update the sample article’s presentation and any minimum content fields necessary to validate the template correctly.

FAQ AND STRUCTURED DATA

- Add an accessible FAQ accordion component when the article includes real FAQ content.
- Accordion triggers must be buttons with accurate expanded/collapsed state.
- Ensure full keyboard support.
- Only output FAQ structured data when the visible page contains matching FAQ content and the implementation is consistent with current search-engine requirements.
- Do not generate hidden or mismatched schema content.

ARTICLE ENDING

The bottom of each article should support this order:

1. Concise conclusion
2. Contextual primary CTA
3. FAQ block, when present
4. Related stories
5. Optional newsletter signup

- Include a subtle “Back to the Journal” link near the end rather than duplicating it at the top.
- Related stories should use the visual treatment established for the redesigned blog landing page.
- Avoid ending the page abruptly after the final paragraph.

CMS / DATA REQUIREMENTS

Confirm or add fields for:

- Display title
- SEO title
- Meta description
- Dek / short introduction
- Category
- Geography/market
- Author, if used
- Publication date
- Last updated date
- Reading time or source text needed to calculate it
- Hero image
- Hero alt text
- Hero focal point/object position
- Table-of-contents inclusion or automatic generation
- Article content blocks
- FAQ items
- Primary CTA label and destination
- Optional product/collection recommendation
- Related articles
- Canonical URL
- Social-sharing image

- Provide safe fallbacks for all optional fields.
- Existing articles must continue rendering without requiring immediate manual migration.
- Document any content migration required for older articles.

SEO AND LOCALIZATION

- Preserve existing article URLs unless an intentional redirect plan is approved.
- Preserve or improve canonical tags, hreflang behavior, Open Graph tags, and social metadata.
- Keep a single indexable H1.
- Use semantic H2/H3 hierarchy.
- Ensure breadcrumb markup remains accurate.
- Validate Article/BlogPosting and BreadcrumbList structured data where used.
- Prevent duplicate titles, duplicate canonicals, and market/language leakage.
- All UI labels and CMS content must support localization, including RTL if Arabic is supported.
- CTA destinations and article recommendations must remain in the selected locale and market.
- Verify the sample path and its equivalent localized URLs.

ACCESSIBILITY

- Meet WCAG AA contrast requirements.
- Use semantic article, nav, aside, heading, list, figure, figcaption, and button/link markup.
- Maintain visible keyboard focus across navigation, CTA, share, TOC, FAQ, and commerce components.
- Ensure tap targets are at least 44 × 44 px where applicable.
- Provide descriptive alt text and avoid redundant alt text on decorative images.
- Ensure the reading order remains logical when sidebars collapse.
- Respect prefers-reduced-motion.
- Verify with keyboard-only navigation and an automated accessibility scan.
- Check at least one screen-reader path through the article intro, TOC, body, FAQ, and related content.

RESPONSIVE REQUIREMENTS

Validate at approximately:

- 1440 px desktop
- 1024 px small desktop/tablet landscape
- 768 px tablet
- 375 px mobile

Expected behavior:

- Desktop may use intro text beside the hero image if consistent with the approved design direction, but title must remain before or alongside—not below—the hero.
- Tablet should retain clear hierarchy without cramped three-column content.
- Mobile should stack intro, CTA, hero, table of contents, body, callouts, and recommendations in a logical order.
- Prevent horizontal overflow, clipped headings, awkward H1 wrapping, and image distortion.
- Sticky elements must not cover content or compete with the global header.
- The first article heading/body content should appear reasonably early after the hero on all breakpoints.

PERFORMANCE

- Avoid adding a large new JavaScript dependency for the template.
- Use responsive images with correct intrinsic dimensions.
- Lazy-load below-the-fold media.
- Prioritize the actual LCP image correctly.
- Prevent cumulative layout shift from images, accordions, related cards, or recommendations.
- Preserve or improve current Core Web Vitals.
- Confirm no material regression in LCP, CLS, INP, or total transferred page weight.
- Avoid loading product data or scripts when the optional commerce module is not used.

ANALYTICS

Validate or add events for:

- Primary intro CTA click
- Share action
- Table-of-contents navigation
- Product/collection recommendation impression
- Product/collection recommendation click
- Related-story click
- Newsletter signup, if displayed

- Use the existing naming convention and analytics provider.
- Do not double-fire events during client-side navigation or hydration.
- Confirm market, locale, article slug, and placement are available as event context where supported.

BROWSER AND QA COVERAGE

Test current supported versions of:

- Safari
- Chrome
- Mobile Safari
- Chrome on Android

QA must cover:

- Header and selectors
- Breadcrumbs and back navigation
- CTA URL and market/locale retention
- Share behavior and fallback
- Hero image cropping and alt text
- TOC anchors
- Heading hierarchy
- All editorial content blocks
- Commerce-module empty and populated states
- FAQ keyboard behavior
- Related stories
- Analytics events
- Canonical/hreflang/schema output
- Long titles and missing optional fields
- Slow image loading
- 200% browser zoom
- Keyboard-only navigation

ACCEPTANCE CRITERIA

- The article title, dek, metadata, and primary CTA appear before or alongside the hero image—not below it.
- The user can understand the article’s topic and take the primary action within the first viewport at 1440 × 900.
- The hero is visibly less dominant and contains no third-party branding.
- The body copy uses a comfortable reading width and clear typographic hierarchy.
- The template supports an optional responsive table of contents.
- Editorial callouts, FAQs, related stories, and commerce recommendations are reusable CMS-driven components.
- Commerce elements remain contextual and visually secondary.
- Existing articles render safely with fallbacks and without broken layouts.
- Header, market, locale, cart, search, and navigation behavior are unchanged.
- Existing URLs and SEO equity are preserved.
- Accessibility review finds no new critical or serious issues.
- No material Core Web Vitals regression is introduced.
- Analytics events are verified once per interaction.
- The sample article is reviewed and approved on staging at desktop, tablet, and mobile widths.

- Short QA report covering browsers, responsiveness, accessibility, analytics, SEO, structured data, and performance.
- Migration notes for older articles, if required.
- List of intentionally deferred follow-up work and dependencies.
