Objective

Keep the primary checkout action visible on desktop by moving “Continue to Payment” into the right-hand Order Summary panel, directly below the Delivery Summary editor.

Scope

- Apply this change to the desktop checkout only.
- Preserve the existing mobile checkout CTA behavior.
- Do not redesign the recipient form, sender form, pricing section, delivery selector, or other checkout content as part of this task.

Approved desktop layout

Use the approved design direction inside the right-hand Order Summary card:

1. Product summary
2. Promo-code control
3. Subtotal, delivery fee, and total
4. Free-delivery message
5. Delivery Summary editor with the existing “Change” action
6. Full-width primary CTA
7. Compact secure-checkout reassurance

CTA design

- Place the CTA immediately below the Delivery Summary editor inside the same Order Summary card.
- Use one full-width Presentail dark-teal button.
- Button copy should be dynamic:
- “Continue to Payment · $72” in the current example
- Replace $72 with the customer’s live checkout total and active currency
- Add a right-arrow icon aligned at the far right.
- Keep the button approximately 56–60 px high with comfortable horizontal padding.
- Use the existing Presentail border radius, typography, colors, and focus styles.
- Directly below the button, show a small lock icon and “Secure checkout” in muted text.
- Do not add a second CTA in the left form column on desktop.

Sticky desktop behavior

- Keep the entire Order Summary panel sticky while the customer scrolls through Recipient Details and Sender Details.
- Use an appropriate top offset below the checkout header.
- Ensure the card remains fully visible on common laptop and desktop viewport heights.
- If the card is taller than the available viewport:
- Keep the CTA accessible
- Avoid covering content
- Use a safe internal layout or scrolling approach without creating nested-scroll confusion
- The sticky panel must stop before the page footer and must not overlap other components.

Dynamic total behavior

Update the amount inside the CTA immediately when any of the following changes:

- Delivery method or delivery fee
- Delivery district
- Promo or gift-card code
- Cart contents or quantity
- Currency
- Taxes or other checkout charges

The amount displayed in the CTA must always match the Total shown immediately above it.

Validation behavior

- Keep the CTA enabled so customers can understand how to proceed.
- When clicked:
- Validate all required fields in the Delivery Details step
- If information is missing or invalid, do not advance
- Highlight the affected field
- Scroll and focus the first invalid field
- Show a clear inline error message
- When all required information is valid, proceed to the Payment step using the existing checkout flow.
- Preserve entered form data when validation fails.
- During submission, show a loading state and prevent duplicate clicks.

Delivery Summary interaction

- Keep the existing Delivery Summary editor and “Change” action directly above the CTA.
- If the delivery selection changes, update the delivery fee, Total, CTA amount, and displayed delivery summary together.
- Do not allow stale totals or delivery details to remain visible while recalculation is in progress.

Accessibility

- Maintain accessible color contrast.
- Give the button and arrow an appropriate accessible label.
- Provide a clear keyboard focus state.
- Announce validation errors and total updates appropriately to screen readers.
- Ensure the button remains usable at increased browser zoom and text size.

Localization

- Support English, Arabic, and French.
- Format currency according to Presentail’s existing currency rules.
- Support RTL placement and text flow in Arabic.
- Allow longer translated CTA copy to fit without clipping; reduce decorative spacing before reducing legibility.

Acceptance criteria

- On desktop, the CTA appears directly below the Delivery Summary editor in the right-hand Order Summary panel.
- The right-hand summary remains visible while scrolling through the checkout form.
- The CTA displays the live checkout total and active currency.
- The amount inside the CTA always matches the Total in the summary.
- Clicking with incomplete information scrolls to and focuses the first invalid field.
- Clicking with valid information advances to Payment.
- Loading behavior prevents duplicate submissions.
- Delivery, promo, district, currency, and cart changes update the CTA total correctly.
- The summary and CTA do not overlap the header, footer, or form content.
- Mobile checkout remains unchanged.
- English, Arabic, and French layouts work across supported desktop sizes.

Objective

Implement the checkout Order Summary state shown only when the customer has reached the configured free-standard-delivery threshold.

Scope

- Implement only the reached-threshold/unlocked state.
- Do not implement the below-threshold progress card, remaining-amount calculation UI, progress bar, or “Add another gift” action as part of this task.
- Apply the unlocked state anywhere the desktop checkout Order Summary displays delivery pricing.
- Preserve the approved “Continue to Payment” placement below Delivery Summary.

Trigger logic

Show the unlocked state when the cart’s eligible subtotal is greater than or equal to the active city’s configured free-standard-delivery threshold.

- Use the same backend eligibility and subtotal calculation used by checkout.
- Do not create a separate frontend-only calculation that can disagree with the charged delivery fee.
- Treat an order exactly at the threshold as eligible.
- Recalculate eligibility after changes to:
  - Cart items or quantities
  - Promo/gift-card codes
  - Delivery city or district
  - Currency
  - Any other adjustment that affects the eligible subtotal
- If the order later falls below the threshold, remove the unlocked state and return to the website’s existing below-threshold behavior. Do not implement the newly proposed actionable below-threshold design in this task.

Unlocked visual state

Replace the current generic free-delivery message with a restrained success card:

- Use a teal circular checkmark icon.
- Headline: “Free standard delivery unlocked”
- Supporting text: “You saved [standard delivery fee] on delivery.”
- Example: “You saved $7 on delivery.”
- Use a white rounded card with the existing subtle border/shadow.
- Use Presentail teal for the icon and success emphasis.
- Do not show a progress bar, threshold goal, orange progress color, confetti, or shopping link after the threshold is reached.

Pricing summary behavior

When standard delivery is selected and the threshold is reached:

- Change the Standard delivery line to show the original fee struck through, followed by “Free” in teal.
- Example: “Standard delivery   $7  Free”
- Remove the standard-delivery fee from Total.
- Ensure the Total shown in the summary and the amount inside “Continue to Payment” match exactly.
- Format the original fee and all totals using the active currency and Presentail’s existing rounding rules.

Express-delivery protection

Reaching the threshold unlocks free standard delivery only.

If Express delivery is selected:

- Do not remove or reduce the Express surcharge.
- Keep the Express delivery fee in the pricing summary and Total.
- Do not state that the customer saved the Express fee.
- Use clear supporting copy such as:
  “Standard delivery is free. Express delivery includes an additional fee.”
- The delivery method, delivery fee, Total, and payment CTA amount must remain consistent.

Delivery Summary and CTA

- Preserve the existing Delivery Summary editor and “Change” action.
- Preserve the full-width desktop CTA directly below it.
- Update the CTA amount whenever free standard delivery is applied.
- Example after reaching a $90 threshold:
  - Subtotal: $90
  - Standard delivery: $7 struck through + Free
  - Total: $90
  - CTA: “Continue to Payment · $90”
- Preserve the “Secure checkout” line below the CTA.

Configuration and currencies

- Read the free-standard-delivery threshold from the active city/country configuration.
- Support locations with different thresholds and standard delivery fees.
- Support all active Presentail currencies and existing formatting rules.
- Do not assume the example values of $90 and $7 are universal.
- If standard delivery is always free for a location, do not display a misleading “saved” amount unless there was an actual fee waived.

Localization and accessibility

- Support English, Arabic, and French.
- Ensure RTL layout works correctly in Arabic.
- Allow translated success copy to wrap without clipping.
- Do not rely only on teal color to communicate success; retain the check icon and explicit unlocked wording.
- Provide accessible text for the success icon and delivery-price change.
- Maintain accessible color contrast and keyboard/screen-reader compatibility.

Acceptance criteria

- The unlocked card appears only when the eligible subtotal meets or exceeds the configured threshold.
- With standard delivery selected, the original standard fee is struck through and “Free” is shown.
- The waived standard-delivery fee is removed from Total.
- The Total and Continue to Payment amount always match.
- The success card displays the correct saved amount and currency.
- Express delivery remains chargeable and is never incorrectly described as free.
- Eligibility and totals update correctly after cart, promo, city, district, or currency changes.
- Falling below the threshold removes the unlocked state and returns to the current existing behavior.
- No below-threshold progress or “Add another gift” UI is introduced.
- English, Arabic, and French render correctly on supported desktop sizes.
- The existing mobile experience and unrelated checkout sections remain unchanged unless they already share this same pricing component and require the calculation fix.
