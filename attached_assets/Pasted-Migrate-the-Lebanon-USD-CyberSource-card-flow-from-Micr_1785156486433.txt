Migrate the Lebanon + USD CyberSource card flow from Microform/direct REST payment orchestration to CyberSource Unified Checkout with Payer Authentication enabled.

CyberSource has requested that the checkout use Unified Checkout before production launch.

We must preserve 3-D Secure/Payer Authentication.

Required final flow
Unified Checkout session
→ Unified Checkout card interface
→ Payer Authentication / 3DS
→ frictionless or issuer challenge
→ authorization and capture
→ final approved payment result
→ order confirmation
Critical requirement

Include:

{
  "completeMandate": {
    "type": "CAPTURE",
    "consumerAuthentication": "3DS"
  }
}

consumerAuthentication: "3DS" must remain enabled. Do not set it to NONE and do not remove Payer Authentication.

CyberSource documents that when Unified Checkout is used with consumerAuthentication: "3DS", device data is collected through Payer Authentication and Unified Checkout completes all calls associated with Payer Authentication.

Eligibility

Use this flow only when:

const useCyberSource =
  senderCountryCode?.trim().toUpperCase() === "LB" &&
  currency?.trim().toUpperCase() === "USD";

All other countries or currencies must continue using Stripe and the existing payment methods unchanged.

Replace the active Microform path

For Lebanon + USD, replace:

/microform/v2/sessions
Microform card fields
custom payer-auth setup
custom device-data iframe
custom enrollment request
custom challenge modal
custom validation request
/payment/cybersource/charge
direct /pts/v2/payments

with Unified Checkout.

Keep the existing code temporarily behind a disabled rollback flag, but do not run it when Unified Checkout is enabled.

Unified Checkout session endpoint

Add:

POST /api/payment/cybersource/unified-checkout/session

This route must call the official CyberSource Unified Checkout session API using the existing production REST Shared Secret credentials and merchant:

blom_presentail1

The capture-context request must include the exact current Unified Checkout fields required by CyberSource, including:

{
  "targetOrigins": [
    "<exact production checkout origin>"
  ],
  "clientVersion": "<supported current version>",
  "country": "LB",
  "locale": "en_US",
  "allowedPaymentTypes": [
    "PANENTRY"
  ],
  "allowedCardNetworks": [

  ],

    "type": "CAPTURE",

      "code": "<unique paymentAttemptId>"

      "amountDetails": {

Use the official current schema rather than guessing field names or versions.

Frontend

Use the official Unified Checkout JavaScript library:

const client = await window.VAS.UnifiedCheckout(sessionJwt);
const checkout = await client.createCheckout({
  autoProcessing: true
});
const paymentResult = await checkout.mount(
  "#cybersource-unified-checkout"
);

Confirm the exact API against the installed/current CyberSource documentation.

With completeMandate included, Unified Checkout can return the completed payment result through auto-processing.

device-data iframes

setup calls
enrollment calls

Unified Checkout must own those steps.

Payment processing configuration

Confirm CyberSource has enabled payment processing for Unified Checkout.

Use:

Sale / immediate capture

if the current checkout captures payment immediately.

CyberSource states that automatic orchestration of 3DS requires payment processing to be enabled; when payment processing is disabled, Unified Checkout only returns payment information and automatic 3DS orchestration is disabled.

Order gate

Do not confirm or mark an order paid until Unified Checkout returns:

{
  approved: true,
  requestId: "<non-empty CyberSource request ID>",
  status: "<approved payment status>"
}

If the payment fails, authentication fails, the customer cancels the challenge, or no request ID is returned:

do not mark paid
do not send paid confirmation
keep the order unpaid or payment-pending

First implementation scope

Initially enable only:

"allowedPaymentTypes": ["PANENTRY"]

Do not add Apple Pay or Google Pay during the first migration test.

After Unified Checkout card payment and Payer Authentication are verified, add:

"allowedPaymentTypes": [
  "PANENTRY",
  "APPLEPAY",
  "GOOGLEPAY"
]

Unified Checkout officially supports these payment types in its capture context.

Acceptance criteria

Do not mark complete until:

The frontend uses Unified Checkout instead of Microform for Lebanon + USD.
The backend creates a Unified Checkout session.
The request contains:
"completeMandate": {
  "type": "CAPTURE",
  "consumerAuthentication": "3DS"
}
Payment processing is enabled for the merchant’s Unified Checkout configuration.
A frictionless 3DS test succeeds.
A challenge test opens the issuer verification flow.
A failed or cancelled challenge does not create a paid order.
The final payment appears in CyberSource Business Center.
The order stores the CyberSource request ID.
No custom Direct Payer Authentication endpoint executes during the Unified Checkout transaction.
Non-Lebanon or non-USD checkout remains unchanged.
