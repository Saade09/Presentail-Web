The latest full-site audit covered 269 sitemap URLs.

1. Fix the Homepage Markdown Mirror

Current problem

The homepage Markdown implementation appears to resolve incorrectly to:

https://presentail.com.md

This is invalid.

The homepage must have a valid and predictable Markdown mirror.

Required implementation

Create a working homepage Markdown endpoint using one of these patterns:

https://presentail.com/index.md

or:

https://presentail.com/home.md

Prefer:

https://presentail.com/index.md

unless the current routing architecture strongly favors another valid path.

Required behavior

The homepage HTML at:

https://presentail.com/

must include:

<link
  rel="alternate"
  type="text/markdown"
  href="https://presentail.com/index.md"
/>

The Markdown endpoint must return:

HTTP/1.1 200 OK
Content-Type: text/markdown; charset=utf-8

It must not return:

* HTML
* a redirect loop
* a 404
* a soft 404
* the homepage shell
* an empty response

Content negotiation

When a client requests:

GET /
Accept: text/markdown

return the homepage Markdown representation directly.

Expected header:

Content-Type: text/markdown; charset=utf-8

Normal browser requests must continue receiving HTML.

Do not change browser behavior or normal page rendering.

Required homepage Markdown frontmatter

Use valid YAML frontmatter:

---
title: Online Flower & Gift Delivery | Presentail
description: Order flowers, gifts, cakes, chocolates, balloons, and plants for delivery across Lebanon, the UAE, and Cyprus.
canonical_url: https://presentail.com/
markdown_url: https://presentail.com/index.md
language: en
locale: en
page_type: homepage
site_name: Presentail
last_modified: YYYY-MM-DD
---

Use a real dynamically generated or deployment-based last_modified value.

Do not hardcode a fake date.

Homepage Markdown content

The Markdown should include clean readable sections such as:

# Presentail
> Presentail is an online flower and gift delivery platform serving Lebanon, the UAE, and Cyprus.
## Flower and Gift Delivery
## Delivery Locations
## Popular Categories
## How Ordering Works
## Same-Day and Express Delivery
## Customer Support
## Explore Presentail

Include relevant internal links to:

* Lebanon
* UAE
* Cyprus
* Beirut
* Dubai
* Abu Dhabi
* Flowers
* Birthday gifts
* Anniversary gifts
* Best sellers

All links must use clean canonical URLs.

Do not include:

* tracking parameters
* currency parameters
* session IDs
* customer data
* internal admin URLs
* unpublished products
* inventory costs
* private pricing logic
* API secrets

2. Fix Duplicate H1 Elements Globally

Current problem

Many pages contain two H1 elements.

This appears to be caused by shared page templates or repeated title rendering.

Required behavior

Every indexable public page must contain exactly one <h1>.

Examples:

Correct

<h1>Flower Delivery in Beirut</h1>
<h2>Shop Flowers by Occasion</h2>

Incorrect

<h1>Flower Delivery in Beirut</h1>
<h1>Flower Delivery in Beirut</h1>

Scope

Audit and fix all shared templates used by:

* Homepage
* Country pages
* City pages
* Product pages
* Category pages
* Occasion pages
* Brand pages
* Blog pages
* Search landing pages
* Collection pages

Implementation requirements

Identify the actual cause instead of hiding one heading with CSS.

Do not use:

display: none;

to mask duplicate headings.

Remove the duplicate semantic heading from the DOM.

If a visual heading must remain for design purposes, change it to:

<div>

or:

<p>

or another appropriate non-heading element.

Maintain the existing visual appearance.

Heading hierarchy

Use:

* One H1 per page
* H2 for major sections
* H3 for subsections
* No skipped levels unless structurally justified

Examples:

<h1>Flower Delivery in Dubai</h1>
<h2>Shop by Occasion</h2>
<h3>Birthday Flowers</h3>

3. Add Homepage Hreflang

Current problem

The homepage currently lacks hreflang tags while other localized pages have them.

Required implementation

Add valid hreflang tags to the homepage and ensure each target returns HTTP 200.

Use the actual production locale architecture.

Example only:

<link rel="alternate" hreflang="en-lb" href="https://presentail.com/en-lb/" />
<link rel="alternate" hreflang="ar-lb" href="https://presentail.com/ar-lb/" />
<link rel="alternate" hreflang="fr-lb" href="https://presentail.com/fr-lb/" />

<link rel="alternate" hreflang="ar-ae" href="https://presentail.com/ar-ae/" />
<link rel="alternate" hreflang="fr-ae" href="https://presentail.com/fr-ae/" />
<link rel="alternate" hreflang="en-cy" href="https://presentail.com/en-cy/" />
<link rel="alternate" hreflang="x-default" href="https://presentail.com/" />

Do not copy this blindly.

Generate the tags from the actual supported locale-country combinations in production.

Validation requirements

Every hreflang URL must:

* Return HTTP 200
* Be indexable
* Have a self-referencing canonical
* Have reciprocal hreflang references
* Use absolute HTTPS URLs
* Not redirect
* Not contain query parameters

The homepage should include x-default.

8. Fix Homepage JSON-LD

Current problem

The homepage JSON-LD exists but is missing:

* name or headline
* description
* url

The scanner currently identifies the primary entity incorrectly or incompletely.

Required implementation

Create a clear primary homepage entity.

Recommended structure:

{
  "@context": "https://schema.org",
  "@type": "Organization",
  "@id": "https://presentail.com/#organization",
  "name": "Presentail",
  "url": "https://presentail.com/",
  "description": "Presentail is an online flower and gift delivery platform serving Lebanon, the UAE, and Cyprus.",
  "logo": {
    "@type": "ImageObject",
    "url": "ACTUAL_LOGO_URL"
  }
}

Also add a website entity:

{
  "@context": "https://schema.org",
  "@type": "WebSite",
  "@id": "https://presentail.com/#website",
  "name": "Presentail",
  "url": "https://presentail.com/",
  "description": "Order flowers, gifts, cakes, chocolates, balloons, and plants online with delivery across supported Presentail locations.",
  "publisher": {
    "@id": "https://presentail.com/#organization"
  }
}

FAQ schema

If FAQ content exists visibly on the page, FAQPage schema may remain.

Do not use FAQ schema for content not visibly rendered.

Do not make FAQPage the only or primary identity entity for the homepage.

Validation

Validate JSON-LD for:

* Valid JSON
* Correct absolute URLs
* No duplicate conflicting entities
* Correct organization name
* Real logo URL
* No placeholder data
* No unsupported fake reviews
* No fake aggregate ratings
