OBJECTIVE

Fix the mobile Cart sticky checkout bar so it always shows a concise delivery-date promise beside the item count.

APPROVED DISPLAY

When the customer selects any delivery slot for tomorrow—including a morning slot such as 9 AM–2 PM—the sticky bar must show exactly:

“1 item · Delivery tomorrow”

Do not repeat the delivery time window in the sticky bar. The full time window already appears in Delivery Summary.

SCOPE

This task is limited to the delivery-promise text in the mobile Cart sticky bar. Do not redesign Delivery Summary or make unrelated cart changes as part of this task.

REQUIRED LOGIC

1. If the selected Standard delivery date is today:
   - Show “Delivery today”
   - If the product requirement already distinguishes evening/night slots, use “Delivery tonight” only when the selected slot genuinely qualifies as tonight.

2. If the selected Standard delivery date is tomorrow:
   - Show “Delivery tomorrow”
   - This applies to morning, afternoon, evening, and night windows.
   - Do not include the hours.
   - Example: a selected slot of tomorrow, 9 AM–2 PM must still show only “Delivery tomorrow.”

3. If the selected Standard delivery date is later than tomorrow:
   - Show “Delivery [short date]”
   - Example: “Delivery Fri, 22 Aug”

4. If Express delivery is selected:
   - Preserve the approved Express promise: “Arrives by [time]”
   - Example: “Arrives by 12:08 PM”

5. If no valid delivery date/time is selected:
   - Show “Select delivery time”

6. The output must never be empty. The current screenshot shows “1 item ·” with no promise after the separator for a tomorrow morning slot; this is the bug to fix.

DATE / TIMEZONE RULES

- Calculate today and tomorrow using the delivery destination/store timezone, not the customer’s phone timezone.
- Lebanon orders: Beirut timezone.
- UAE orders: UAE local timezone.
- Recalculate the label if the delivery country, city, date, window, or method changes.
- Recalculate correctly after refresh, browser back navigation, and restoration of a saved cart.

COPY AND FORMATTING

- Keep the item count and delivery promise on the same row whenever space allows.
- Approved example: “1 item · Delivery tomorrow”
- Preserve singular/plural logic:
  - “1 item · Delivery tomorrow”
  - “2 items · Delivery tomorrow”
- Use the existing middle-dot separator.
- Do not show “Standard delivery tomorrow” in the bar.
- Do not show “Tomorrow, 9 AM–2 PM” in the bar.
- Do not show the detailed delivery window in the bar.
- Do not reduce the item-count emphasis or change the total/CTA layout.
- Use the existing translation system; do not hard-code English.

LOCALIZATION

Verify all supported customer languages:
- English
- Arabic, including correct RTL order and alignment
- French

Make sure longer translations do not collide with the Total block. Allow graceful wrapping only if absolutely necessary on narrow screens.

ACCEPTANCE CRITERIA

- Selecting tomorrow, 9 AM–2 PM displays “1 item · Delivery tomorrow.”
- Selecting any other tomorrow slot displays the same date-level promise without its hours.
- The label no longer renders blank after “1 item ·”.
- Today, tonight, future-date, Express, and no-selection states still display correctly.
- Changing the delivery selection updates the sticky label immediately without refreshing.
- Item singular/plural updates correctly.
- Total and Checkout button remain unchanged.
- Delivery Summary continues to show the full selected time window.
- Timezone calculation remains correct when the customer device timezone differs from the delivery location.
- English, French, and Arabic RTL versions pass QA.

QA CASES

2. Multiple items + tomorrow morning slot.
3. Tomorrow afternoon/evening slot.
4. Today daytime slot.
5. Tonight slot.
6. Future scheduled date.
7. Express selected.
8. No slot selected.
9. Switch from today to tomorrow.
10. Switch from Standard to Express and back.
11. Refresh with tomorrow slot already saved.
12. Customer device timezone differs from Beirut/UAE.
13. English, French, and Arabic RTL at 320 px, 375 px, and 430 px widths.
