**Prompt:**

Update the website language-switching behavior so that when a user changes language, the app preserves the selected **country and city route**.

### Current route structure

The URL format should be:

`https://presentail.com/{language-country}/{city}`

Examples:

* English UAE Dubai:
  `https://presentail.com/en-ae/dubai`

* Arabic UAE Dubai:
  `https://presentail.com/ar-ae/dubai`

* French UAE Dubai:
  `https://presentail.com/fr-ae/dubai`

Where:

* `en`, `ar`, `fr` = language
* `ae` = country
* `dubai` = city

---

### Desired behavior

When the user is on:

`/en-ae/dubai`

and changes language to Arabic, redirect them to:

`/ar-ae/dubai`

When the user is on:

`/en-ae/dubai`

and changes language to French, redirect them to:

`/fr-ae/dubai`

When the user is on:

`/ar-ae/dubai`

and changes language to English, redirect them to:

`/en-ae/dubai`

The selected city and country should remain unchanged.

---

### Requirements

1. **Preserve city**

   * Do not send users back to the homepage or country selector when changing language.
   * Keep the city slug exactly the same unless localized city slugs already exist.

2. **Preserve country**

   * Keep the country code from the current locale segment.
   * Example:

     * `/en-ae/dubai` → `/ar-ae/dubai`
     * `/fr-lb/beirut` → `/en-lb/beirut`

3. **Only change language**

   * The language switcher should only replace the language part of the locale segment.
   * Example:

     * Current: `en-ae`
     * New language: `ar`
     * Result: `ar-ae`

4. **Support supported languages**

   * English: `en`
   * Arabic: `ar`
   * French: `fr`

5. **Support existing country codes**

   * Use the existing country codes already supported by the app.
   * Examples:

     * `ae`
     * `lb`
     * `cy`

6. **Fallback behavior**

   * If the current URL does not include a city, preserve the rest of the route as much as possible.
   * Example:

     * `/en-ae` → `/ar-ae`
   * If the current URL has additional path segments, preserve them:

     * `/en-ae/dubai/products/123` → `/ar-ae/dubai/products/123`

7. **RTL behavior**

   * When switching to Arabic:

     * Set `dir="rtl"`
     * Use Arabic translations
   * When switching back to English or French:

     * Set `dir="ltr"`

8. **Do not reset user location**

   * Do not clear saved country/city from local storage or app state.
   * Do not re-trigger the country/city onboarding flow just because language changed.

---

### Implementation guidance

Please inspect the existing routing and language switcher first.

Then update the language switch logic to:

1. Parse the current locale segment from the URL:

   * Example: `en-ae`

2. Extract:

   * language: `en`
   * country: `ae`

3. Replace only the language with the selected language:

   * `ar-ae`
   * `fr-ae`
   * `en-ae`

4. Preserve the remaining path:

   * city slug
   * product route
   * category route
   * query params
   * hash fragments

Example helper behavior:

```ts
switchLanguage('/en-ae/dubai', 'ar') 
// returns '/ar-ae/dubai'

switchLanguage('/fr-lb/beirut/products/rose-123?ref=home', 'en')
// returns '/en-lb/beirut/products/rose-123?ref=home'
```
