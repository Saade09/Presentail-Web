Use this prompt in Presentail App:

⸻

Fix the website’s Markdown mirror and frontmatter implementation directly. Do not only investigate, explain, or provide a plan. Implement the solution, test it, and confirm that the agent-readability scanner no longer reports:

* “No markdown mirror available to check”
* “Markdown frontmatter missing”
* “No alternate Markdown link found”
* “Accept: text/markdown returns HTML”

Objective

Create clean Markdown versions of Presentail’s important public, indexable pages so AI agents and crawlers can read the page content without processing the full HTML or JavaScript application.

Each Markdown mirror must:

* Be publicly accessible
* Return HTTP 200
* Use valid Markdown
* Start with valid YAML frontmatter
* Represent the same content and intent as its corresponding HTML page
* Include the correct canonical URL
* Exclude private, checkout, account, customer, payment, and internal information
* Stay synchronized with the underlying website data

Do not replace the normal website pages. Customers must continue receiving the existing HTML experience.

⸻

1. Create a consistent Markdown mirror URL structure

Use a predictable mapping between every supported HTML page and its Markdown version.

Use the following convention:

* / → /index.md
* /en-lb/beirut → /en-lb/beirut.md
* /en-lb/beirut/shop → /en-lb/beirut/shop.md
* /en-lb/beirut/flowers → /en-lb/beirut/flowers.md
* /en-lb/beirut/occasions/birthday → /en-lb/beirut/occasions/birthday.md
* /en-lb/beirut/product/floral-sun → /en-lb/beirut/product/floral-sun.md

Apply the same pattern to valid public UAE, Cyprus, Arabic, and French routes.

Do not create Markdown mirrors for:

* Cart
* Checkout
* Payment pages
* Account pages
* Login or registration
* Order tracking pages containing customer information
* Admin pages
* Search-result pages
* Preview routes
* Internal APIs
* Temporary pages
* URL parameter variations
* Redirecting or non-canonical pages

Only create Markdown mirrors for canonical, indexable public pages.

⸻

2. Add valid YAML frontmatter

Every Markdown mirror must begin with valid YAML frontmatter.

Use fields appropriate to the page type.

Example:

---
title: "Flower & Gift Delivery in Beirut"
description: "Order flowers, cakes, plants, chocolates and gifts for delivery across Beirut with Presentail."
canonical_url: "https://presentail.com/en-lb/beirut"
markdown_url: "https://presentail.com/en-lb/beirut.md"
language: "en"
locale: "en-LB"
country: "Lebanon"
city: "Beirut"
page_type: "location"
site_name: "Presentail"
last_modified: "2026-07-22"
---

Required fields for all Markdown pages:

* title
* description
* canonical_url
* markdown_url
* language
* locale
* page_type
* site_name
* last_modified

Where relevant, also include:

* country
* city
* category
* occasion
* recipient
* brand
* product_name
* product_slug
* sku
* price
* price_currency
* availability
* image
* breadcrumbs

Do not include empty or fake values.

Do not expose internal IDs unless they are already public and useful.

Do not expose database details, supplier costs, margins, recipes, inventory quantities, customer information, API keys, or internal configuration.

Frontmatter formatting requirements

* The file must begin immediately with ---.
* The frontmatter must close with another ---.
* Use valid YAML.
* Quote strings where necessary.
* Use ISO dates such as 2026-07-22.
* URLs must be absolute HTTPS URLs.
* The canonical URL must point to the normal HTML page.
* The Markdown URL must point to the .md version.
* Do not include tracking or currency parameters.
* Do not canonicalize Markdown pages to legacy URLs.
* Do not include duplicated YAML keys.
* Ensure special characters, colons, and quotation marks are escaped correctly.

⸻

3. Generate meaningful Markdown content

The Markdown body must provide a clean, structured version of the corresponding public page.

Do not simply dump raw HTML, navigation markup, JavaScript state, or serialized application data.

Use logical Markdown headings.

Example:

# Flower & Gift Delivery in Beirut
Presentail provides flower and gift delivery across Beirut, including same-day and scheduled delivery where available.
## Shop
- [All Products](https://presentail.com/en-lb/beirut/shop)
- [Flowers](https://presentail.com/en-lb/beirut/flowers)
- [Birthday Gifts](https://presentail.com/en-lb/beirut/occasions/birthday)
- [Plants](https://presentail.com/en-lb/beirut/plants)
## Popular Products
- [Floral Sun](https://presentail.com/en-lb/beirut/product/floral-sun)
- [Product name](canonical product URL)
## Delivery Information
Delivery availability, fees and delivery times depend on the recipient’s address, selected date and available delivery slots.
## Frequently Asked Questions
### Does Presentail offer same-day delivery in Beirut?
Same-day delivery may be available depending on the delivery address, product and time of ordering.

The Markdown content must reflect the page’s actual visible content.

Do not invent:

* Products
* Prices
* Stock
* Delivery times
* Reviews
* Discounts
* Free-delivery thresholds
* Service areas
* Payment methods

When data changes dynamically, generate the Markdown from the same source used by the website.

5. Category and occasion Markdown mirrors

For category and occasion pages, include:

* Page title
* Short useful description
* Location context
* Product links
* Related categories
* Related occasions
* Delivery information
* FAQs where present on the HTML page

Do not include hundreds of products without limits.

Use a reasonable number of featured or currently visible products, and provide a link to the canonical category page.

If pagination exists, avoid creating uncontrolled Markdown duplicates for every sort and filter variation.

6. Add the alternate Markdown link to HTML pages

Every HTML page that has a Markdown mirror must include this in its <head>:

<link
  rel="alternate"
  type="text/markdown"
  href="https://presentail.com/en-lb/beirut.md"
/>

Requirements:

* Use the correct Markdown URL for the current page.
* Use an absolute HTTPS URL.
* Include exactly one Markdown alternate link.
* Do not point every page to the homepage Markdown file.
* Do not add this link to pages without a Markdown mirror.
* Do not use legacy, redirecting, parameterized, or non-canonical URLs.

The existing HTML canonical tag must continue pointing to the normal HTML page, not the Markdown mirror.

⸻

7. Support Markdown content negotiation

When a crawler requests a public canonical page using:

Accept: text/markdown

return the Markdown representation of that same page.

Example:

Request:

GET /en-lb/beirut
Accept: text/markdown

Expected response:

* HTTP 200
* Content-Type: text/markdown; charset=utf-8
* The same content as /en-lb/beirut.md
* Valid YAML frontmatter at the beginning

A normal browser request must continue receiving HTML:

GET /en-lb/beirut
Accept: text/html

Expected response:

* HTTP 200
* Content-Type: text/html; charset=utf-8
* Existing customer-facing page

Do not redirect normal visitors to Markdown.

Do not return HTML while claiming the response is Markdown.

Do not return Markdown to normal website visitors unless their request explicitly asks for Markdown.

⸻

8. Add HTTP discovery headers

For HTML responses with a Markdown mirror, add a valid HTTP Link response header.

Example:

Link: <https://presentail.com/en-lb/beirut.md>; rel="alternate"; type="text/markdown"

For the Markdown response, include a link to the canonical HTML page.

Example:

Link: <https://presentail.com/en-lb/beirut>; rel="canonical"; type="text/html"

Ensure the HTML tag, HTTP header, frontmatter URLs, and actual page URLs all agree.

⸻

9. Add a Markdown sitemap section

Each Markdown page should end with a concise discovery section where useful.

Example:

## Site Navigation
- [Presentail Home](https://presentail.com/)
- [Beirut Store](https://presentail.com/en-lb/beirut/shop)

Do not duplicate the entire website navigation or create excessively long files.

Ensure /sitemap.md, /llms.txt, and /llms-full.txt reference the clean canonical HTML URLs and, where useful, the Markdown mirrors.

⸻

10. Indexing and canonical behavior

The Markdown mirror is an alternate machine-readable representation, not a separate search landing page competing with the HTML page.

Requirements:

* HTML pages remain the primary canonical pages.
* Markdown frontmatter must identify the HTML page as canonical_url.
* Do not add Markdown URLs to the normal XML SEO sitemap unless there is a deliberate technical reason.
* Do not allow Markdown mirrors to create duplicate search results.
* Do not create Markdown mirrors for query-parameter URLs.
* Requests such as /en-lb/beirut.md?utm_source=google must still identify the clean Markdown and HTML URLs.
* Markdown mirrors must never contain advertising or currency parameters in links.
* Legacy URLs must not receive their own Markdown mirrors.
* Redirect legacy URLs to the new HTML canonical route first.

Markdown mirrors are public.

Ensure they never include:

* Customer names
* Customer phone numbers
* Customer email addresses
* Recipient information
* Addresses
* Order details
* Payment information
* Internal employee information
* Internal API endpoints
* API keys
* Environment-variable values
* Database connection details
* Private administration URLs
* Supplier costs
* Product margins
* Inventory quantities
* Internal product recipes
* Server paths
* Debug output
* Application state containing private data

Only expose information already intended to be public on the corresponding website page.

⸻

12. Performance and caching

Markdown responses should be lightweight and fast.

Implement appropriate caching while ensuring content updates when:

* Product details change
* Product availability changes
* Prices change
* Category content changes
* Location content changes
* SEO content changes

Do not generate expensive full-site Markdown files on every request when they can be safely cached or statically generated.

Do not allow stale Markdown to display a materially different price or availability from the HTML page.
