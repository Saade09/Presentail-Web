Improve the Purchase Order detail page so customer service agents can create and upload a supplier invoice directly from the PO, without navigating to the supplier page or the separate Invoices module.

Current problem:
On a PO, clicking “Link Invoice” only allows the user to search for an invoice that already exists. If no invoice exists, the panel displays “No invoices found,” forcing the user to leave the PO, open the supplier, create the invoice, then return and link it. This workflow is unnecessarily complicated.

Required changes:

1. Update the “Link Supplier Invoice” panel
Add two clear options at the top:

- Upload New Invoice — default selection
- Link Existing Invoice

The user must be able to complete either workflow without leaving the purchase order.

2. Upload New Invoice workflow
Reuse the existing “Add Invoice” functionality currently available under the supplier’s Invoices tab, but adapt it for the current PO.

Include these fields:

- Invoice file upload — required
- Invoice number
- Invoice amount — required
- Currency — required
- Issue date — required
- Status
- Paid-on date, displayed when relevant
- Notes — optional

Support PDF, JPG, JPEG, and PNG files. Include both drag-and-drop and “Choose file” functionality. Show the selected filename, file size, upload progress, and an option to remove or replace the file before submitting.

3. Automatically prefill and link data
Because the invoice is being created from a PO:

- Automatically select the PO’s supplier.
- Automatically link the invoice to the current PO.
- Prefill the currency from the PO.
- Prefill the invoice amount using the PO grand total.
- Prefill the issue date with today’s date.
- Do not ask the user to choose a supplier or PO again.
- Allow the user to change the amount, currency, date, and other editable invoice details before submitting.

Display a short summary above the form:

- PO number
- Supplier
- PO total
- Currency
- Location

4. Submission behavior
Use a primary button labeled “Upload & Link Invoice.”

After submission:

- Create the supplier invoice using the same underlying invoice records and logic as the existing supplier invoice feature.
- Save the uploaded document as an attachment to that invoice.
- Link the invoice to the current PO automatically.
- Refresh the PO’s “Linked Invoices” and “Invoice Status” sections immediately.
- Close the side panel.
- Show a success notification such as: “Invoice uploaded and linked to PO-0005.”
- Do not create duplicate invoice or PO-link records if the user clicks twice or the request is retried.

5. Link Existing Invoice workflow
Preserve the current invoice-search workflow under the “Link Existing Invoice” option.

- Default the search results to invoices belonging to the current PO’s supplier.
- Allow searching by invoice number, amount, date, or supplier.
- Show invoice number, issue date, amount, currency, and status in every result.
- Prevent an invoice already linked to this PO from being linked again.
- Keep the optional linking notes field.
- Disable the “Link Invoice” button until an invoice is selected.

If there are no matching invoices, show:

“No existing invoices found for this supplier.”

Below it, provide a prominent “Upload New Invoice” button that switches the panel to the new-invoice form.

6. PO page empty state
In the “Linked Invoices” card, replace the single ambiguous “Link Invoice” action with:

- Primary: “Upload Invoice”
- Secondary: “Link Existing”

The primary workflow should be uploading a new invoice because this is the most common customer service use case.

7. Permissions
Customer service agents who can view and manage purchase orders must be able to upload and link invoices from this page. Do not unintentionally grant them access to unrelated accounting or supplier-management actions.

Reuse the project’s existing invoice permissions where appropriate, but ensure the customer service role can complete this specific PO workflow.

8. Validation and error handling

- Validate required fields before submission.
- Prevent unsupported file types and oversized files using the application’s existing upload limits.
- Detect a likely duplicate using supplier + invoice number. Warn the user and offer to link the existing invoice instead of silently creating another.
- Preserve entered form data if the upload or API request fails.
- Show clear inline errors and allow retrying.
- Do not mark the invoice as successfully linked unless both invoice creation and PO linking succeed.
- Follow the project’s existing transaction/error-recovery patterns so partial records are not left behind.

9. Compatibility
Use the existing database structure, storage system, APIs, components, styling, and invoice creation logic wherever possible. Do not build a separate invoice system. Maintain the existing three-way matching functionality and ensure invoices created here also appear in:

- The PO’s Linked Invoices section
- The supplier’s Invoices tab
- The main Procurement → Invoices module

Make the panel responsive and usable on desktop and mobile.

Acceptance criteria:

- A customer service agent can open a PO and upload a supplier invoice without navigating elsewhere.
- The supplier and PO are assigned automatically.
- The invoice document is stored and viewable/downloadable afterward.
- The new invoice appears immediately on the PO, supplier, and main invoices pages.
- Existing invoices can still be searched for and linked.
- Duplicate creation and duplicate linking are prevented.
- Invoice totals, status, and three-way matching update correctly.
- Role permissions and the existing invoice workflows continue to work.
- Relevant automated tests are added or updated for invoice creation, file upload, PO linking, duplicate prevention, authorization, and failure recovery.

Before implementing, inspect the current PO-linking flow and the existing supplier “Add Invoice” implementation. Reuse and consolidate their shared logic rather than duplicating it. Test the complete workflow using the customer service role.
