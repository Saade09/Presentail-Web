
Objective
Improve the two preference controls beneath the WhatsApp Number field in the mobile Sender Details card. The layout should be tighter, better aligned, and easier to use by making each entire row tappable.

Critical scope restriction
Mobile checkout only, recommended at viewport widths of 767 px and below.
Do not change the tablet or desktop layout as part of this task.
Change only the “Get order updates on WhatsApp” and “Send this gift anonymously” controls, plus the Sender Details card height required by the more compact layout.


Approved design reference
Use the latest approved mockup shared in the ChatGPT conversation. Preserve the existing Presentail checkout styling and avoid nested bordered cards.

1. WhatsApp updates row
Keep the option checked by default, matching the existing approved behavior.
Use a visible checkbox of approximately 24 × 24 px in Presentail dark teal.
Provide a minimum 44 × 44 px touch target around the checkbox.
Place the checkbox on the far left of the row.
Place the green WhatsApp icon immediately before the title.
Vertically align the checkbox, WhatsApp icon, and first line of the title.
Use this exact title: “Get order updates on WhatsApp”.
Use this exact helper text: “We’ll send order and delivery updates to this number. Opt out anytime.”
Position the helper text 4–6 px below the title.
Indent the helper text so it starts beneath the title text, not beneath the checkbox or WhatsApp icon.
Keep the helper readable but visually subordinate using the existing secondary-text style.


2. Anonymous gift row
Keep the option unchecked by default, matching the existing behavior.
Use the same visible checkbox size, border treatment, and 44 × 44 px touch target as the WhatsApp row.
Vertically align the checkbox with the first line of the title.
Use this exact title: “Send this gift anonymously”.
Use this exact helper text: “Your name won’t appear on the gift card or recipient notifications.”
Position the helper text 4–6 px below the title.
Indent the helper text so it begins directly beneath the title.


3. Spacing and visual grouping
Reduce the vertical gap between the two rows to approximately 16 px.
Add a very subtle horizontal divider between the two options, matching the approved mockup.
The divider should begin at the card’s content edge and remain visually quiet.
Keep efficient but comfortable spacing above the first option and below the second option.
Reduce the Sender Details card height only by removing unnecessary space; do not compress the form fields above.
Do not place either preference inside a bordered inner card or heavy background.


4. Full-row tap behavior
The full width of each preference row must toggle its associated checkbox.
Tapping the title, helper text, WhatsApp icon, whitespace, or checkbox must all work.
Ensure tapping the checkbox itself triggers only one state change; avoid duplicate click handlers that toggle twice.
The two rows must remain independent—tapping one must never change the other.
Do not require customers to tap the small visible checkbox precisely.
Keep sufficient separation so customers do not accidentally activate the neighboring row.


5. Interaction states
Provide restrained pressed, hover, and keyboard-focus feedback across the entire row.
Pressed feedback may use a very subtle neutral background or opacity change; do not make the row look like a nested card.
Use a clear focus-visible outline for keyboard users.
Retain the current dark-teal checked state and neutral grey unchecked state.


6. Accessibility
Implement each control as a semantic checkbox with its title and helper associated as the accessible label/description.
Expose the correct checked state to assistive technology.
The decorative WhatsApp icon should not become a separate keyboard-focus target.
Maintain at least a 44 × 44 px interactive target.
Ensure checked, unchecked, pressed, and focus-visible states meet contrast requirements.
Screen readers should announce the option name, state, and relevant helper text once—without duplication.


7. Preserve existing functionality
The WhatsApp opt-in must continue saving and submitting through the same existing field and backend logic.
The anonymous-gift selection must continue controlling whether the sender’s name appears on the gift card and recipient notifications.
Do not change defaults, validation, API payloads, order creation, customer records, or notification logic.
Do not change the WhatsApp Number input or its country selector.
Do not change the sticky checkout footer, total, delivery summary, Sender Details fields, or payment navigation.


Localization
Apply the layout and full-row behavior in English, French, and Arabic.
Use natural translated copy rather than literal translations.
For Arabic/RTL, mirror checkbox and content alignment correctly while preserving the full-row touch target.
Allow longer translated titles and helper text to wrap without overlapping the checkbox or divider.


Acceptance criteria
Both preference rows match the approved compact layout on mobile.
Checkboxes are the same visible size and vertically aligned with their respective titles.
The WhatsApp icon is aligned with the WhatsApp title and does not affect checkbox alignment.
Each helper sits 4–6 px below its title and starts beneath the title text.
The rows are separated by approximately 16 px and a subtle divider.
The full width of each row is tappable.
Tapping any point in a row changes its checkbox exactly once.
The two controls remain independent.
WhatsApp updates remain checked by default and anonymous gifting remains unchecked by default.
The Sender Details card becomes more compact without changing the fields above.
No nested-card visual noise is introduced.
Existing order, notification, opt-in, and anonymous-gift functionality remains unchanged.
English, French, and Arabic/RTL pass visual and functional QA.
Tablet and desktop remain unchanged.
