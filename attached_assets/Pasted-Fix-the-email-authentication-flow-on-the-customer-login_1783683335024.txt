Fix the email authentication flow on the customer login page.

Current problem:
When a customer enters an email address that already belongs to an account originally created with Google or Apple, clicking “Continue with Email” shows the generic error:

“Something went wrong, please try again.”

Required behavior:
1. Detect whether the entered email already exists.
2. Detect which authentication provider is linked to that account:
   - Google
   - Apple
   - Email/password or email-link login
3. When the account exists but is linked only to Google or Apple, do not show a generic error.
4. Show a clear warning message instead:

For Google:
“An account already exists with this email using Google. Please continue with Google to sign in.”

For Apple:
“An account already exists with this email using Apple. Please continue with Apple to sign in.”

If both providers are linked:
“An account already exists with this email using another sign-in method. Please continue with Google or Apple.”

5. Keep the user on the login page and visually highlight the relevant Google or Apple button.
6. Do not create a duplicate account.
7. Do not expose whether arbitrary email addresses exist through a public unauthenticated database query. Use the authentication provider’s secure sign-in or account-linking response to determine the existing login method.
8. Replace generic frontend error handling with mapped, user-friendly messages for known authentication errors.
9. Keep “Something went wrong, please try again” only for genuine unknown server or network failures.
10. Make email comparison case-insensitive and trim spaces before submission.
11. Add logs for the real authentication error code and provider, but do not log tokens, passwords, verification codes, or other sensitive data.
12. Test these cases:
   - Existing Google account entered through email
   - Existing Apple account entered through email
   - Existing normal email account
   - New email address
   - Email with uppercase letters or spaces
   - Unknown server failure
   - No duplicate customer record is created

Inspect the current authentication backend and frontend before changing anything. Fix the root error handling rather than only replacing the toast text.
