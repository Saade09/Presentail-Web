
Objective
Improve the Lebanon checkout location dropdown so customers can find and select a delivery area quickly without the menu taking over the page. The implementation should match the approved mockup from Adnan’s ChatGPT review.

Page / scope
Customer-facing checkout: https://presentail.com/en-lb/beirut/checkout
Apply to the first location dropdown and its relationship with the second location field.
Lebanon checkout first. Preserve all existing delivery-area availability rules and downstream checkout logic.


Required UI changes
Add a clearly visible label above the first field: Governorate *.
When opened, anchor the menu directly under the field and keep it exactly the same width as the field.
Cap the open menu height at approximately 320–360px. The list must scroll internally instead of extending over most of the checkout page.
Add a compact search field at the top with a search icon and placeholder: Search governorates.
Use approximately 46–48px row height with consistent horizontal padding and alignment.
Display the selected location with a very light teal background and a dark teal checkmark aligned to the right.
Use a 14px corner radius, thin neutral border, and restrained shadow consistent with the rest of checkout.
Keep the second location field visible beneath the menu. Label it City / District * and preserve the selected value.


Search behavior
Search should filter as the customer types.
Match case-insensitively and ignore leading/trailing whitespace.
Search both available and unavailable locations.
Keep the selected item visible when no search is active.
Show a compact, helpful empty state when no location matches, for example: No governorates found.
Clearing the search restores the full list and the customer’s existing selection.


Available and unavailable locations
Preserve availability from the current backend/configuration; do not hard-code the locations shown in the mockup.
Show available locations first.
Group unavailable locations at the bottom under the divider and uppercase section label: CURRENTLY UNAVAILABLE.
Unavailable rows must remain readable in muted gray and include a small lock icon.
Unavailable rows must not be selectable by mouse, touch, or keyboard.
Do not use extremely faint text or repeat “Not available at the moment” after every item.
If every location is available, hide the unavailable section entirely.


Interaction requirements
Clicking or tapping an available row selects it, updates the field, closes the menu, and refreshes the dependent City / District options using existing logic.
Clicking outside or pressing Escape closes the menu without changing the selection.
Opening the menu again should clearly show the current selection.
Do not reset an already valid City / District selection unnecessarily. Reset it only when the new first-field selection makes it invalid.
Prevent the menu from being clipped by parent cards or hidden behind the Order Summary.


Keyboard and accessibility
Tab focuses the field; Enter or Space opens it.
Arrow Up/Down navigates enabled options.
Enter selects the highlighted enabled option.
Escape closes and returns focus to the trigger.
Skip disabled options during keyboard navigation.
Provide appropriate combobox/listbox semantics, selected state, disabled state, accessible labels, and visible focus styling.
Maintain WCAG-compliant contrast for labels, selected state, disabled text, and focus state.


Responsive behavior
Desktop/tablet: menu width equals the field width; maximum height remains compact.
Mobile: respect the page’s 16px gutters, avoid horizontal overflow, keep search sticky at the top while the options scroll, and ensure rows remain easy to tap.
The menu must remain usable with the mobile keyboard open.


States to implement
Closed/default
Open with selection
Search active with results
Search with no results
Available option hover/focus
Unavailable option
Loading dependent City / District data
Error loading options with a retry path


Acceptance criteria
The open dropdown no longer exceeds roughly 360px in height.
The search is present, fast, and correctly filters the complete data set.
The selected item is visually obvious and announced correctly to assistive technology.
Unavailable locations are grouped once, readable, locked, and impossible to select.
The City / District field and its label remain understandable and are not unnecessarily obscured.
All existing pricing, delivery availability, selected-address, and checkout validation logic continues to work.
No layout shift or collision occurs with Delivery Details or the Order Summary.
Verified on Chrome and Safari on desktop, plus iPhone and Android mobile widths.


QA scenarios
Select Beirut, close the menu, reopen it, and confirm Beirut remains highlighted.
Search for an available location and select it.
Search for an unavailable location and confirm it appears locked and cannot be selected.
Search for a nonexistent term and verify the empty state.
Change the first field and confirm dependent City / District choices refresh correctly.
Navigate the complete component with keyboard only.
Test with a long translated location name and at 200% browser zoom.
Test mobile scrolling while the on-screen keyboard is open.


Out of scope
Do not change delivery coverage, prices, eligibility rules, or the underlying location hierarchy in this task.
Do not redesign other checkout sections.
