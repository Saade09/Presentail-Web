Please redesign and improve the **Homepage Banners → New Banner / Edit Banner** experience in Presentail OS.

The current modal works, but it feels too long, too form-heavy, and too technical. I want it redesigned into a cleaner, more premium, marketing-friendly banner creation flow.

Use the attached/reference mockup as the target direction.

## Goal

Create a much better banner creation/editing interface for the Presentail OS admin panel that allows the marketing team to easily:

* Create homepage banners
* Upload desktop and mobile media
* Target banners by country and city
* Select where the banner links
* Schedule banners
* Preview how the banner will look before publishing
* Save as draft, schedule, publish, pause, or duplicate banners

The page should feel like a polished SaaS admin tool, not a database form.

---

## Current page to improve

Page:
`/admin/homepage-banners`

Current action:
Click **New Banner**

Current modal has:

* Internal name
* Title
* CTA text
* Headline
* Subtitle
* Targeting
* Desktop media
* Mobile media
* Link type
* Start/end dates
* Timezone
* Sort order
* Priority
* Active toggle
* Preview at bottom

Problems:

* The modal is too long vertically.
* Preview is too low and requires scrolling.
* Upload fields expose technical `/storage/objects/...` paths.
* “Active” is unclear when combined with schedule.
* Desktop and mobile media sections are not intuitive enough.
* Link target wording is too technical.
* Required field validation appears inside the preview, which feels odd.
* Bottom action buttons disappear when scrolling.
* The form does not clearly summarize what will happen when the banner is published.

## 12. Replace Active toggle with proper status

The current “Active” toggle is confusing.

Use a clear status model:

Possible statuses:

* Draft
* Scheduled
* Active
* Paused
* Expired

Rules:

* Draft: not visible on website.
* Scheduled: will become active at start date.
* Active: currently visible, assuming date rules match.
* Paused: hidden even if within schedule.
* Expired: end date has passed.

The UI should show the computed status clearly in the summary.

For example:
Status pill:
`Scheduled`

Or:
`Active`

Or:
`Draft`

Do not rely only on a simple Active toggle.

---

## 13. Sort order and priority

Please review whether both are actually needed.

Preferred approach:
Use one clear field:

**Display priority**

`Higher priority banners appear first when multiple banners match the same country, city, device, and schedule.`

Use a numeric input.

If both `sort_order` and `priority` are required in the backend, keep both internally but simplify the UI.

# Backend / Data Handling Requirements

Please preserve existing data and avoid breaking existing banners.

Migration requirements:

* Existing banners should continue to work.
* Map old `active` field into the new status model.
* If active = false, treat as Draft or Paused depending on current data.
* If active = true and start/end dates are valid, status should compute as Active/Scheduled/Expired.
* Do not delete old fields unless safely migrated.
* Keep API compatibility with the public website.

Add or confirm fields:

* internal_name
* title
* headline
* subtitle
* cta_text
* countries
* cities or city_targeting_mode
* languages
* desktop_enabled
* desktop_media_url
* desktop_media_type
* mobile_enabled
* mobile_media_url
* mobile_media_type
* destination_type
* destination_id or destination_url
* start_at
* end_at
* timezone
* status or status_override
* priority
* created_at
* updated_at

Computed status logic:

* Draft if saved as draft
* Paused if manually paused
* Scheduled if start_at is in the future
* Active if current time is between start_at and end_at, and not paused
* Expired if end_at has passed

# Acceptance Criteria

The task is complete when:

1. The New Banner modal/page uses a two-column layout with form on the left and live preview on the right.
2. Preview is visible without scrolling to the bottom.
3. Desktop and mobile media upload areas are clear and do not show `/storage/objects/...` paths.
4. Targeting is clearer with country chips and all-cities/specific-cities choice.
5. Link target is renamed to Banner click destination.
6. Schedule is easier to understand with Draft / Publish now / Schedule options.
7. Active toggle is replaced or improved with clear status behavior.
8. Sticky footer includes Cancel, Save draft, and Publish/Schedule banner.
9. Publishing summary shows status, targeting, devices, schedule, destination, and priority.
10. Validation is clear and appears near the relevant field.
11. Existing banners still work after the change.
12. Main homepage banners list still supports edit, preview, duplicate, pause/resume, and delete.
13. UI is responsive and usable on laptop-sized screens.
14. No existing homepage banner functionality is broken.
15. The final result visually matches the attached mockup direction.
