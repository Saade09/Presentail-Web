
Redesign and implement the Beirut flower-delivery landing page so it guides customers through discovery, builds trust early, and converts better without turning into one uninterrupted product catalog.

Route:
- /en-lb/beirut/flower-delivery
- Apply the same responsive component system to equivalent localized/language versions where the existing routing architecture supports it.

Use the attached approved desktop and mobile mockups as the primary visual references.

## Core implementation principles

- Preserve Presentail’s existing premium visual language: ivory background, dark teal, serif display headings, restrained sans-serif UI copy, rounded cards, and studio product photography.
- Preserve the intentionally simplified header. Do not add desktop category navigation.
- Build reusable, data-driven components. Do not hard-code Beirut-specific products, rating totals, delivery promises, or review content into presentation markup.
- Reuse existing product, inventory, delivery-slot, location, review, currency, and localization sources.
- This must be a permanent responsive implementation, not separate brittle desktop/mobile pages.
- Keep performance, SEO, accessibility, and analytics intact.

## Responsive and UI requirements

- Mobile content gutters: 16 px.
- Use consistent responsive spacing and component tokens rather than page-specific magic numbers.
- Suggested breakpoints should follow the existing design system.
- No unintended horizontal overflow; only marked carousels may scroll horizontally.
- Maintain minimum 44 × 44 px touch targets where practical.
- Preserve rounded-corner and typography consistency.
- Test long localized text, different currencies, large prices, cart count, and dynamic review counts.
- Verify at representative widths: 320, 375, 390, 430, 768, 1024, 1280, and 1440+ px.

## Accessibility

- Logical heading order with one H1.
- Descriptive alt text for meaningful photography; decorative images use empty alt attributes.
- Visible keyboard focus states.
- Sufficient color contrast.
- All carousel, accordion, location, CTA, and header controls keyboard accessible.
- Respect reduced-motion preferences.
- Do not rely on color alone for availability or badges.

## Performance

- Protect Core Web Vitals.
- Optimize hero and product images with responsive sources, correct dimensions, and modern formats.
- Preload only the true LCP image.
- Lazy-load below-the-fold images and non-critical widgets.
- Reserve space for Trustpilot and product imagery to prevent CLS.
- Avoid duplicate Trustpilot scripts/widgets.
- Keep client-side JavaScript minimal and reuse existing components.

## Analytics

Track or preserve existing events for:

- Compact Trustpilot strip click
- Occasion shortcut click
- Product impression and product click
- View all flowers

Use existing event naming conventions and do not duplicate events already emitted by shared components.

## Acceptance criteria

- Simplified header remains exactly as approved; no desktop category navigation is introduced.
- Hero uses dynamic delivery-promise logic and never displays an impossible time.
- Delivery selector updates relevant availability, timing, fees, and content.
- Compact Trustpilot strip appears directly under the delivery selector on desktop and mobile.
- Full Trustpilot carousel remains lower on the page.
- Both Trustpilot modules use live/shared data and do not duplicate script loading.
- Product section displays only eligible products for the active location.
- Desktop uses a four-column product grid; mobile uses two columns.
- Mobile carousels are swipeable, have no accidental page overflow, and expose the next item visually.
- Repetitive “In stock” labels and duplicate cutoff messaging are removed.
- FAQ content and schema match current operations.
- Page works across all specified breakpoints, languages, currencies, and empty/error/loading states.
- No material regressions to search, account/cart, checkout routing, product tracking, SEO, accessibility, or Core Web Vitals.
- QA confirms visual alignment with both attached mockups.
