Objective

Audit and optimize this entire Replit project so that:

* The application runs faster
* Deployment workers use fewer resources
* Replit usage and infrastructure costs are reduced
* Builds, restarts, and deployments are faster and more reliable
* Replit Agent can understand and modify the project more efficiently in future tasks
* The codebase becomes easier and safer to maintain

This task concerns the Replit workspace, application runtime, deployment configuration, background workers, and development environment. It does not concern any customer-facing AI agent inside the application.

Important Approach

First understand the project’s architecture and measure its current performance. Then make targeted, permanent improvements.

Do not perform a broad rewrite.

Do not change the user interface, business rules, APIs, database behavior, or working features unless a change is necessary to correct a verified performance problem.

Do not delete files, dependencies, processes, or workers unless you confirm they are unused.

Audit the Workspace

Inspect:

* Application architecture and entry points
* .replit and other Replit configuration
* Development and production commands
* Build and deployment processes
* Running processes and deployment workers
* Background jobs, scheduled jobs, queues, and consumers
* CPU and memory consumption
* Worker concurrency and scaling configuration
* Database queries and connection pooling
* External API calls
* Caching
* Application startup time
* Frontend bundle size
* Server response times
* Installed dependencies
* Logging volume
* Retry loops, polling, timers, and persistent connections
* Memory leaks and processes that do not terminate correctly
* Duplicate services or jobs
* Outdated or conflicting project documentation

Identify anything that unnecessarily consumes:

* Replit compute
* Worker time
* CPU
* Memory
* Database connections
* Storage
* Network requests
* Build time
* Agent context

Optimize the Runtime and Workers

Look specifically for:

* Workers running when no work exists
* Duplicate workers processing the same job
* Jobs polling too frequently
* Unbounded concurrency
* Missing job timeouts
* Infinite or excessive retries
* Jobs that remain stuck
* Memory leaks
* Heavy work running inside web-request processes
* Database connections that are not released
* Unnecessary always-on processes
* Schedules running more frequently than required
* Multiple processes performing the same responsibility
* Worker settings that are too large or too small for actual demand

Configure workers based on measured workload. Do not blindly reduce capacity if doing so could harm reliability.

Where appropriate, implement:

* Safe concurrency limits
* Exponential backoff
* Retry limits
* Job timeouts
* Graceful shutdown
* Idempotency protection
* Connection reuse
* Query batching
* Caching
* Event-driven processing instead of frequent polling
* Removal of confirmed duplicate work

Optimize the Application

Investigate and permanently fix:

* Slow or repeated database queries
* N+1 query patterns
* Duplicate API requests
* Blocking operations
* Unnecessary frontend requests
* Oversized responses
* Repeated calculations
* Excessive logging
* Large or unused dependencies
* Slow application startup
* Inefficient build steps
* Rebuilding components that have not changed
* Missing production caching or compression
* Errors that cause repeated restarts or retries

Do not hide errors merely to reduce logs. Fix their root causes.

Improve Replit Agent Effectiveness

Make the project easier for Replit Agent to understand and work on safely.

Inspect any existing project instruction and architecture files. Remove conflicting or outdated instructions only after confirming they are incorrect.

Create or update concise project documentation covering:

* What each application and major directory does
* Production entry points
* Development and deployment commands
* Worker responsibilities
* Database architecture
* External integrations
* Important business rules
* How to run tests
* How to verify changes
* Files or systems that must not be modified casually
* Common failure modes
* The correct permanent-fix approach for bugs

Keep this documentation accurate and concise so it improves Agent context rather than adding unnecessary information.

Verification

Establish a baseline before making changes, then compare it with the optimized version.

Measure where possible:

* Application startup time
* Build time
* Deployment time
* Average API response time
* CPU usage
* Memory usage
* Number of active processes
* Number and utilization of workers
* Database query volume
* Database connection count
* External request volume
* Background-job completion time
* Error and retry rates
* Frontend bundle size
* Estimated compute or infrastructure reduction

Run the existing test suite after every meaningful group of changes. Add targeted tests for any performance or reliability problem you fix.

Verify that:

* The application starts correctly
* All existing features continue working
* Background jobs run once and complete correctly
* Workers shut down gracefully
* Deployments remain stable
* Database connections are released
* No scheduled task was accidentally disabled
* No production secret or configuration was exposed
* No data was deleted or modified unexpectedly

Deliverable

Complete the audit and implement safe, verified improvements.

At the end, provide a clear report containing:

1. The project architecture you found
2. The root causes of inefficiency
3. Every file and configuration changed
4. Worker and deployment improvements
5. Application performance improvements
6. Improvements made to help Replit Agent work better in the future
7. Before-and-after measurements
8. Estimated impact on Replit usage and cost
9. Tests performed and their results
10. Remaining opportunities that require my approval

Do not state that the project is optimized unless you have measured and verified the result. If a proposed change could affect production reliability, data, or business behavior, stop and request approval before making that specific change.
