Investigate and fix incorrect navigation for the cross-city SEO links on Presentail category and occasion pages.

## Bug

On this page:

https://presentail.com/en-lb/beirut/category/cakes

Clicking “Cake delivery in Tripoli” should navigate to:

https://presentail.com/en-lb/tripoli/category/cakes

Instead, client-side navigation sometimes produces:

https://presentail.com/en-lb/beirut/en-lb/tripoli/category/cakes

The current Beirut route is incorrectly being prepended to the complete Tripoli route.

This likely affects other cross-city links and languages too, including routes beginning with:

* `/en-lb/`
* `/ar-lb/`
* `/fr-lb/`

It may affect cakes, chocolate, balloons, Mother’s Day, and other SEO-generated category or occasion links.

## Likely cause

The application uses Wouter with nested/scoped routes.

The affected SEO content appears to render links approximately like this:

```tsx
sections.map((section) => (
  <div>
    {section.links?.map((link) => (
      <Link href={link.href}>{link.label}</Link>
    ))}
  </div>
))
```

A link such as:

```text
/en-lb/tripoli/category/cakes
```

is already a complete application path. However, when it is passed to Wouter’s `Link` inside the scoped Beirut router, Wouter treats it as belonging to the current route scope and prepends `/en-lb/beirut`.

The server-rendered HTML contains the correct `href`, but client-side click handling produces the duplicated path.

### Recommended safe fix

For the custom SEO text links, render native anchor elements because their destinations are already complete paths:

```tsx
<ul className="mt-3 flex flex-wrap gap-x-4 gap-y-1">
  {section.links.map((link) => (
    <li key={link.href}>
      <a
        href={link.href}
        className="text-sm underline underline-offset-4 text-foreground/80 hover:text-foreground"
      >
        {link.label}
      </a>
    </li>
  ))}
</ul>
```

This is the preferred solution for these SEO links because:

* Root-relative paths such as `/en-lb/tripoli/category/cakes` will resolve from the domain root.
* Absolute URLs such as `https://presentail.com/...` will work correctly.
* Navigation will not inherit the current nested Wouter route.
* Crawlers and users will receive the same destination.
* A full-page navigation for these lower-page SEO links is acceptable and safer than incorrectly scoped SPA navigation.

### Alternative if SPA navigation must be preserved

Wouter uses `~/` to bypass a nested router’s base. Only complete localized application paths should receive this prefix:

```tsx
function getSeoRouterHref(href: string) {
  const isLocalizedRootPath =
    /^\/(?:en|ar|fr)-[a-z]{2}\//i.test(href);

  return isLocalizedRootPath ? `~${href}` : href;
}
```

Then:

```tsx
<Link href={getSeoRouterHref(link.href)}>
  {link.label}
</Link>
```

Do not pass external `http://` or `https://` URLs to Wouter’s `Link`. Render those with a native `<a>`.

Unless there is a strong architectural reason to preserve SPA routing here, use the native-anchor solution.

## Important constraints

* Do not hardcode Tripoli or Beirut.
* Do not solve this by removing URL segments after navigation.
* Do not alter the current city stored in application state merely because an SEO link was clicked.
* Do not change valid URL data into relative paths like `en-lb/tripoli/...`.
* Do not add redirects as the primary fix. Prevent the malformed URL from being generated.
* Preserve the existing link labels, classes, visual styling, and SEO content.
* Do not modify unrelated navigation links that intentionally use route-relative paths such as `/category/cakes` inside the current city scope.
* Ensure external links continue to work.
* Check whether both custom SEO content and the generic `SEOContentSection` have the same problem.
