Objective
Standardize the spacing, typography, and alignment between field labels and their corresponding controls in the checkout “Recipient Details” section. The current vertical rhythm varies between the recipient name, phone number, delivery district, and delivery details fields.

Design specification
- Use 8px between each label row and its associated input/control.
- Use 24px between the bottom of one input/control and the next label row.
- Keep a consistent label line-height of 20px.
- Use the same label font size, weight, and color for every field.
- Use sentence case for all labels:
  - Recipient name
  - Phone number
  - Delivery district
  - Delivery details
- Position the red required asterisk 4px after the label and align it to the text baseline.
- For Phone number, position the information icon 8px after the required asterisk and vertically center it with the label.
- Maintain comfortable separation between the “Ask the recipient for the address” option card and the first form label.
- Do not change the existing field widths, heights, border radius, placeholders, dropdown arrow, country selector, textarea size, colors, or overall card structure.

Implementation guidance
- Wrap each label and input/control in the same reusable FormField structure.
- Apply spacing at the field-group level rather than with one-off margins on individual labels or controls.
- The component must behave consistently for:
  - Standard text inputs
  - Phone number input with country selector
  - Select/dropdown controls
  - Multiline textarea
- Remove any field-specific margin overrides causing the larger gap above Delivery district or tighter gap around Delivery details.
- Preserve existing validation, focus, error, disabled, and filled states.
- Apply the same spacing rules on desktop and mobile unless a documented responsive token already exists.

Acceptance criteria
1. Every field label is exactly 8px above its associated control.
2. Every completed control is exactly 24px above the following label row.
3. All four labels use identical typography and sentence case.
4. Required asterisks have identical spacing and baseline alignment.
5. The Phone number information icon is consistently aligned and remains clickable.
6. No visual or functional regressions occur in the phone selector, district dropdown, or textarea.
7. Validation and error messages do not break the spacing rhythm; when displayed, they belong to the current field group and preserve separation before the next field.
8. Desktop and mobile checkout views use the same consistent pattern.
9. The change does not affect the sign-in card, “Ask the recipient for the address” behavior, Delivery Summary, Order Summary, or sticky checkout bar.

QA checklist
- Test desktop and mobile widths.
- Test empty, filled, focused, invalid, disabled, and autofilled states.
- Test long translated labels in English, Arabic, and French.
- Verify RTL alignment in Arabic.
- Confirm keyboard navigation and screen-reader label association remain intact.
- Compare the finished implementation with the approved mockup from this conversation.
