## Objective

Increase the clickable/tappable target of the delivery option cards in the cart’s **Delivery Summary**. No visual redesign is required; preserve the current UI exactly.

## Required behavior

### When Standard delivery is selected

- Make the entire **Express delivery** card clickable/tappable, not only the **Upgrade** button.
- Clicking anywhere within the Express card must perform the same upgrade action as clicking **Upgrade**.
- The upgrade must immediately:
  - select Express delivery;
  - refresh the arrival time;
  - update the delivery charge in Order Summary;
  - update the total;
  - update the checkout CTA total.
- The **Upgrade** button must remain visible and continue to work.

### When Express delivery is selected

- Preserve the current selected design shown in production: one Express delivery card with the **Change** action.
- Make the entire selected Express card clickable/tappable.
- Clicking anywhere within it must perform the same action as **Change** and reopen the delivery selection options.
- The **Change** action must remain visible and continue to work.

### Standard card consistency

- When applicable within the delivery-option chooser, make the full Standard delivery card clickable as well so users can switch options consistently.
- Do not create nested or conflicting click behavior between the card and its Upgrade/Change control.
- One user interaction must trigger only one state change or popup.

## Interaction and responsive requirements

- Desktop: show a pointer cursor over the full clickable card and apply only a very subtle hover response consistent with the existing design system.
- Keyboard: the card must be focusable and operable using Enter and Space.
- Provide a visible focus state that matches the existing accessibility styling.
- Mobile/tablet: the full card must be a reliable tap target across its entire width.
- Ensure the behavior works at all supported responsive breakpoints without overflow, clipped text, or layout changes.

## Design constraints

- No redesign is required.
- Keep the current colors, borders, spacing, typography, icons, price placement, **Upgrade** button, and **Change** action.
- Do not add a checkmark, stronger border, new background treatment, radio button, or extra explanatory copy.
- Preserve the current selected Express state exactly.

## Technical notes

- Use semantic interactive markup where practical. If the card cannot be a native button because it contains another interactive control, implement an accessible wrapper pattern with correct role, tab index, keyboard handlers, and event handling.
- Prevent event bubbling from causing duplicate requests or opening the selector twice.
- Preserve loading/disabled protection while the delivery update is being processed.
- Avoid double submission from rapid repeated clicks/taps.
- Maintain analytics tracking; the full-card click should emit the same upgrade/change event as the existing control.

## Acceptance criteria

1. With Standard selected, clicking the Express card’s icon, label, arrival time, whitespace, price, or Upgrade button selects Express.
2. With Express selected, clicking the card’s icon, label, arrival time, whitespace, or Change action opens the delivery selector.
3. Price, arrival time, Order Summary, total, and checkout CTA stay synchronized after every switch.
4. Only one action occurs per click/tap.
5. The existing visual design remains unchanged except for subtle desktop hover and keyboard focus feedback.
6. Keyboard users can reach the card and activate it with Enter or Space.
7. The full card is tappable on mobile and remains fully visible at small screen widths.
8. Existing Upgrade and Change controls continue to work.
9. Test Standard → Express → Change → Standard on desktop and mobile.
10. No regression to scheduled, same-day, or unavailable delivery-slot behavior.
