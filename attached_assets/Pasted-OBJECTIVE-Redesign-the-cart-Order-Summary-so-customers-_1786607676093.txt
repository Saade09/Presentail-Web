OBJECTIVE

Redesign the cart Order Summary so customers can understand the full price composition in under three seconds:

Items → standard delivery → express upgrade (when selected) → promo → total → checkout.

The current summary uses generic labels such as “Subtotal,” “Delivery charges,” and “Express fee,” which make the financial story harder to scan. The approved design uses concrete labels, separates the base standard-delivery charge from the express upgrade, moves promo code entry inside the summary, and supports qualified free-delivery states without creating pricing ambiguity.

APPROVED INFORMATION HIERARCHY

Order Summary

1. Items
2. Standard delivery
3. Express upgrade, only when selected/applicable
4. Promo code
5. Divider
6. Total
7. Secure checkout CTA

All monetary values must be server-authoritative and formatted consistently for the active locale and currency.

GLOBAL LAYOUT REQUIREMENTS

• Keep “Order Summary” as the card heading.
• Replace “Subtotal” with “Items ([item count]).”
• Right-align every amount to a single clean column.
• Use medium weight for row labels and amounts.
• Place supporting explanations directly beneath their corresponding label in smaller muted text.
• Maintain compact but comfortable vertical spacing between financial groups.
• Total and final amount should be visually dominant but restrained.
• Do not use an oversized decorative total.
• Keep the CTA full width inside the card.
• Move “Add a promo code” from the standalone pill above Delivery Summary into the Order Summary.
• Remove the standalone promo pill and move Delivery Summary upward into the reclaimed space.
• Preserve a consistent vertical gap between Delivery Summary and Order Summary.
• Order Summary height should adapt to visible rows; do not reserve blank space for absent rows.
• Preserve Presentail’s existing typography, white cards, dark-teal accents, rounded corners, shadows, and sidebar width.

STATE D — EXPRESS DELIVERY, FREE STANDARD DELIVERY UNLOCKED

Express upgrade                           AED 60

[Promo row]

[Divider]

Total                                      AED 410

[Lock icon] Checkout securely · AED 410

Business rule:

• Free standard delivery removes the base standard-delivery charge.
• Express upgrade remains payable.
• In the example: AED 350 + AED 60 = AED 410.

Requirements:

• Never imply that qualifying for free standard delivery makes express free.
• Keep “Free” and the express fee visually distinct.
• Use backend pricing as the source of truth.
• If the actual business rules do not waive the base charge when express is selected, reflect the backend calculation and update the label/supporting copy accordingly. Do not force the mockup’s arithmetic over production rules.
• Do not show the separate free-delivery success banner in the main cart column while express is selected; communicate the saving inside Order Summary.

PROMO CODE INTERACTION

Collapsed row:

[Tag icon] Add a promo code [Chevron]

Requirements:

• Place it below pricing groups and above the total divider.
• Make it visually secondary.
• Entire row is clickable.
• Minimum target size: 44 × 44 px.
• Preserve keyboard focus styling.
• Chevron indicates collapsed/expanded state.
• Do not open a modal unless the existing product pattern requires one.

Expanded state:

• Inline promo-code input.
• “Apply” action.
• Validation/loading state.
• Clear inline error message for invalid, expired, ineligible, or usage-limited codes.
• Applied-code state shows the code and a clear “Remove” action.
• Prevent duplicate submissions while applying.
• Preserve the cart if the request fails.
• Announce result to assistive technology.

When a promo is applied:

• Add a discount row if the promotion changes the payable amount.
• Example:
  “Promo · FLOWERS10”                   “−AED 10”
• Use a minus sign and consistent currency formatting.
• Recalculate delivery eligibility, standard-delivery saving, express fee, and total atomically.
• Do not show stale free-delivery copy after a promo changes the qualifying subtotal.
• If the promo creates free delivery, label that benefit according to the actual promotion, not as threshold-unlocked unless that is true.

CTA

Approved format:

[Lock icon] Checkout securely · [formatted total]

Requirements:

• Replace “Proceed to Checkout.”
• Use the actual current payable total.
• Keep the lock icon decorative if the text already conveys secure checkout.
• Button spans the card width.
• Preserve existing dark-teal background and white text.
• Maintain a minimum 44 px height.
• Show disabled/loading behavior only while checkout initialization requires it.
• Do not make a security claim beyond the checkout’s actual secure transport/payment implementation.
• If “securely” conflicts with legal/brand guidance, confirm the final CTA with Product before launch; otherwise use the approved wording.

CURRENCY AND NUMBER FORMATTING

• Use one currency format everywhere within the cart.
• Example: “AED 140,” never a mix of “AED 140,” “د.إ 140,” and symbol-only amounts in the same locale.
• Use the locale’s established format through the shared money formatter.
• Never hard-code AED or any example amount.
• Correctly support decimals, thousands separators, currencies with zero decimals, and RTL currencies.
• Negative discounts/savings must be formatted consistently.
• Values in Order Summary, CTA, and checkout payload must all derive from the same pricing response.

ITEM COUNT

• “Items (1)” should reflect the intended product-count definition.
• Confirm whether item count means line items or total quantity; use the product-wide cart convention consistently.
• Correct pluralization/localization.
• Quantity changes update count and values immediately without a full refresh.

ATOMIC PRICING UPDATES

Update the following together from one authoritative cart/quote response:

• Item count and items subtotal
• Standard-delivery charge/free status
• Standard-delivery saving
• Express-upgrade row and amount
• Promo/discount row
• Other applicable taxes/fees, if any
• Total
• CTA total
• Free-delivery state
• Delivery promise metadata

Avoid transient mismatches such as:

• Summary total differs from CTA.
• “Free” appears while the old delivery fee is still included.
• Express row persists after switching to standard.
• Discount applies to the total before the discount row appears.
• Delivery promise updates without the related fee update.

If recalculating:

• Keep the previous stable values or use a restrained loading state.
• Do not flash zeroes.
• Prevent checkout using stale totals if the backend requires revalidation.
• Do not block checkout for purely visual failures when pricing remains valid.

• Express row appears only when express is selected/applicable.
• Supporting explanations appear beneath their corresponding labels.
• Standalone promo pill is removed.
