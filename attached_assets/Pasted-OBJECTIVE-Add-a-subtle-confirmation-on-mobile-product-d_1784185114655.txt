OBJECTIVE

Add a subtle confirmation on mobile product detail pages when the displayed product price alone qualifies the order for free standard delivery in the customer’s selected delivery city.

The purpose is to make free delivery feel like an earned benefit at the purchase-decision point, instead of relying only on the reassurance card farther down the page.

APPROVED DESIGN

Add a compact inline success message directly below the price/points row and above the product title:

✓ This order qualifies for free standard delivery

Design requirements:
- Use a small circular check icon in Presentail dark teal.
- Use dark-teal text consistent with the approved mockup.
- Keep the treatment lightweight and premium.
- Do not use a large alert, filled green banner, progress bar, or card.
- Keep comfortable but compact spacing above and below the message.
- Shift the product title and following content down only as much as necessary.
- Preserve the existing product-page hierarchy and styling.
- This task must not change the existing free-delivery reassurance card.

SCOPE

- Mobile product detail pages.
- English, Arabic, and French.
- All supported countries, cities, and currencies.
- All standard, sale-price, and configurable products.
- Use the city delivery settings already managed in Presentail OS as the source of truth.
- Desktop is out of scope unless the mobile and desktop components share implementation and the same approved presentation can be maintained without unintended layout changes.

DISPLAY LOGIC

Show the confirmation only when at least one of the following is true:

1. The product’s current active selling price is greater than or equal to the free-standard-delivery threshold configured for the customer’s selected city.
2. The product has an explicit free-standard-delivery override, if such a product-level rule exists.

Example:
- Selected city: Beirut
- Beirut free-delivery threshold: $90
- Product price: $360
- Result: Show “This order qualifies for free standard delivery”.

Hide the message when:
- The product price is below the selected city’s free-delivery threshold.
- The selected city has no free-delivery threshold configured.
- Standard delivery is unavailable for the selected city/product/date.
- The required city or pricing data is still loading.
- The delivery configuration cannot be retrieved or validated.

Do not show an inaccurate fallback during loading. The message should appear only after eligibility is confirmed.

PRICE RULES

- Use the current active selling price, not the crossed-out regular price.
- If a product option, size, or configuration changes the product price, recalculate eligibility immediately.
- If a promotion is already reflected in the PDP selling price, use the promotional price.
- Compare values using the platform’s canonical/base monetary values and normal precision—not rounded display strings—to avoid currency-conversion edge cases.
- The price shown on the PDP and the price used for the eligibility check must refer to the same active product configuration.
- A product exactly equal to the threshold qualifies.
- Do not include delivery fees, taxes, tips, or unrelated charges in the eligibility calculation.
- Because this is a PDP message, base eligibility on the current product alone; do not rely on products already in the cart.
- A coupon applied later in the cart/checkout must use the existing cart/checkout free-delivery recalculation rules. This PDP message must not override final delivery-fee calculation.

CITY AND CURRENCY BEHAVIOR

- Use the customer’s currently selected delivery city.
- Recalculate immediately when the customer changes delivery city.
- Use each city’s own free-standard-delivery threshold.
- Currency switching must not change the underlying eligibility result incorrectly.
- The threshold and product price may be displayed in the selected currency, but eligibility should be determined from equivalent canonical values before display rounding.
- If the customer has not selected a delivery city, do not show the confirmation until eligibility can be established accurately.

DELIVERY-METHOD CLARITY

- The message must explicitly say “free standard delivery”.
- It must not imply that express delivery is free.
- Express delivery or premium time-slot surcharges remain subject to existing pricing rules.
- Selecting express delivery must continue to show any applicable additional fee in the delivery selector, cart, and checkout.
- This feature must not modify delivery prices or eligibility rules; it only communicates an existing benefit.

LOCALIZATION

Use approved translations through the existing localization system. Do not hard-code English.

English:
“This order qualifies for free standard delivery”

Arabic:
Use a natural RTL translation approved by the existing Arabic localization process.

French:
Use a natural translation approved by the existing French localization process.

Requirements:
- Preserve correct punctuation and reading order in RTL.
- Keep the icon aligned naturally with each language.
- Avoid awkward wrapping on supported mobile widths.
- Ensure longer French and Arabic text does not overlap the price, points, title, or screen edges.

RESPONSIVE AND ACCESSIBILITY REQUIREMENTS

- Support the smallest mobile viewport currently supported by Presentail.
- Allow clean wrapping to two lines only if necessary; never truncate the benefit or use an ellipsis.
- Maintain sufficient contrast against the white background.
- Treat the icon as decorative if the full benefit is already conveyed by text.
- Do not rely on color alone to communicate eligibility.
- Avoid layout shift where practical while eligibility data is loading.
- The message is informational and should not be clickable.

STATE UPDATES

Recalculate or refresh the message when any of the following changes:
- Selected delivery city.
- Selected currency.
- Product option, variation, size, or configuration.
- Active promotional price.
- Product-specific free-delivery override.
- City free-delivery threshold.
- Standard-delivery availability.

The final delivery fee shown in cart and checkout remains the source of truth.

ANALYTICS

If the existing product-page analytics framework supports lightweight impression events, record an event when the confirmation is displayed:
- Event: free_delivery_qualification_message_viewed
- Include product ID, selected city ID, country ID, displayed currency, current product price, and configured threshold.
- Do not block release if adding this event requires a separate analytics implementation; flag it for follow-up instead.

ACCEPTANCE CRITERIA

- An eligible product shows the exact earned-benefit confirmation below the price/points row and above the product title.
- A product above the threshold shows the message.
- A product exactly equal to the threshold shows the message.
- A product below the threshold does not show the message.
- A product-level free-standard-delivery override shows the message, if overrides are supported.
- Changing to a city with a different threshold updates eligibility correctly.
- Changing a product option that changes the price updates eligibility correctly.
- Sale prices are evaluated using the active selling price.
- Currency changes do not create false eligibility due to display rounding.
- The message never suggests that express delivery is free.
- The component renders correctly in EN, AR, and FR.
- The Arabic version displays correctly in RTL.
- The message is readable without clipping across supported mobile devices.
- Existing product page, Add to Cart, delivery selector, cart, and checkout behavior remain unchanged.
- No free-delivery fee logic is duplicated or overridden in the frontend; use the existing delivery configuration/source of truth.

QA SCENARIOS

1. Beirut threshold $90; product $360 → message shown.
2. Beirut threshold $90; product $90 → message shown.
3. Beirut threshold $90; product $89 → message hidden.
4. Change from a city where the product qualifies to one where it does not → message disappears.
5. Change back to an eligible city → message returns.
6. Switch currency → eligibility remains correct and no flicker/inaccurate interim state appears.
7. Select a lower-priced product variation below the threshold → message disappears.
8. Select a higher-priced variation above the threshold → message appears.
9. Sale price falls below threshold while regular price is above → message hidden.
10. Product with explicit free-standard-delivery override → message shown, if supported.
11. City with no configured free-delivery threshold → message hidden.
12. Express delivery selected → any express surcharge remains visible and charged correctly.
13. English, French, and Arabic/RTL on smallest supported mobile width.
14. Slow or failed delivery-configuration request → no inaccurate qualification message.
15. Verify cart and checkout remain the final source of truth after coupons or order-level changes.
