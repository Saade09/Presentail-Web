’ll outline the practical setup and the exact Replit implementation requirements, because a custom-built site needs a product feed, structured data, shipping/returns, and verification—not just “connecting” a plugin.

Thought for 6s

Yes — since Presentail was built from scratch in Replit, you should treat Google Merchant Center as a custom ecommerce integration, not a Shopify-style plugin.

The best setup for Presentail is:

Verify and claim presentail.com in Google Merchant Center.
Create a product feed endpoint from your website or Presentail OS.
Add product structured data on every product page.
Make sure price, currency, availability, shipping, and returns are accurate.
Connect Merchant Center to Google Ads once products are approved.

Google supports product data through feeds, structured data, ecommerce platform connections, manual upload, Google Sheets, and the Merchant API. For a custom site like yours, the cleanest first version is a scheduled XML/TXT feed plus structured data on product pages. Google specifically says product data must be accurate and formatted correctly to avoid disapprovals or limited eligibility.

What Replit needs to build
1. Website verification support

In Google Merchant Center, you will need to verify/claim your website. Google supports verification through an HTML tag, HTML file, Google Analytics, Google Tag Manager, or ecommerce platform verification.

For Replit, ask them to support both:

adding a Google Merchant Center meta tag to the homepage <head>
serving an uploaded Google verification HTML file from the root domain

Example:

https://www.presentail.com/google123456789.html

This is important because Merchant Center may ask for one of these methods.

2. Product feed endpoint

Create a public feed URL like:

https://www.presentail.com/google-merchant-feed.xml

or per country/city:

https://www.presentail.com/feeds/google-merchant/lb.xml
https://www.presentail.com/feeds/google-merchant/ae.xml

Because Presentail sells by country/city, I would not make one messy global feed at first. I would create feeds by market:

Lebanon feed
UAE/Dubai feed

Each product in the feed should include:

id
title
description
link
image_link
additional_image_link
availability
price
sale_price, if applicable
brand
condition
google_product_category
product_type
shipping
custom_label_0 = country/city
custom_label_1 = occasion/category
custom_label_2 = margin/COGS bucket if useful later

Google lets merchants create product data sources using a file, Google Sheets, or Content API/Merchant API. For your stage, a scheduled feed is simpler and safer than API integration.

3. Structured data on product pages

Every product page should include JSON-LD Product markup with Offer data.

Google says Product markup can make pages eligible for merchant listing experiences on Google Search, including Shopping-related surfaces, Google Images, popular product results, and snippets. Merchant Center can also use structured data to retrieve up-to-date product information from your site.

Example structure Replit should generate dynamically:

<script type="application/ld+json">
{
  "@context": "https://schema.org/",
  "@type": "Product",
  "name": "Red Roses Bouquet",
  "image": [
    "https://www.presentail.com/images/red-roses.jpg"
  ],
  "description": "Fresh red roses bouquet available for delivery in Dubai.",
  "brand": {
    "@type": "Brand",
    "name": "Presentail"
  },
  "sku": "product-123",
  "offers": {
    "@type": "Offer",
    "url": "https://www.presentail.com/en-ae/dubai/products/red-roses-bouquet",
    "priceCurrency": "AED",
    "price": "299.00",
    "availability": "https://schema.org/InStock",
    "itemCondition": "https://schema.org/NewCondition"
  }
}
</script>

Important: the structured data price/currency/availability must match the visible page and feed. Google warns that inaccurate or mismatched product information can cause disapprovals or limited eligibility.

4. Availability by city

This is especially important for Presentail.

If a product is available in Lebanon but not Dubai, the Dubai product feed should either:

exclude the product entirely, or
mark it as out_of_stock if the product page is still accessible

For Merchant Center, I recommend exclude unavailable city products from that city’s feed. This avoids showing a Google Shopping ad for a product that cannot be delivered in that location.

Example:

Cake available in Beirut → include in Lebanon feed
Same cake unavailable in Dubai → exclude from UAE feed
5. Shipping and returns

Merchant Center requires shipping/return settings to be clear. Since Presentail has different delivery fees, free delivery thresholds, and express fees by city, Replit should make sure the site has crawlable pages for:

/shipping-policy
/return-policy
/contact
/terms
/privacy-policy

The feed can include shipping data, but you should also configure shipping settings inside Merchant Center.

Prompt to send to Replit

Copy/paste this:

We need to connect Presentail.com to Google Merchant Center.

Context:
- Presentail is a custom-built ecommerce website, not Shopify/WooCommerce.
- The website supports multiple countries/cities, especially Lebanon and UAE/Dubai.
- Products can be available in one city but unavailable in another.
- Prices and currencies differ by market.
- Google Merchant Center needs accurate product data, structured data, website verification, shipping/returns, and feed support.

Please implement a production-ready Google Merchant Center integration with the following requirements:

1. Website verification support
- Add a configurable setting/env variable for the Google Merchant Center verification meta tag.
- Inject the verification meta tag into the homepage <head> when present.
- Also support serving Google verification HTML files from the root domain if needed, for example:
  /google123456789.html
- Make sure this works on both presentail.com and www.presentail.com if both are supported.

2. Product feed endpoint
Create public Google Merchant Center feed endpoints:
- /feeds/google-merchant/lb.xml
- /feeds/google-merchant/ae.xml
Optional later:
- /feeds/google-merchant/{countryCode}.xml
- /feeds/google-merchant/{countryCode}/{citySlug}.xml

The feed should be valid XML RSS 2.0 with Google Merchant namespace:
xmlns:g="http://base.google.com/ns/1.0"

Each product item should include:
- g:id
- g:title
- g:description
- g:link
- g:image_link
- g:additional_image_link when available
- g:availability
- g:price
- g:sale_price if applicable
- g:brand
- g:condition = new
- g:google_product_category
- g:product_type
- g:shipping when possible
- g:custom_label_0 for country/city
- g:custom_label_1 for category/occasion
- g:custom_label_2 for product margin/COGS bucket if available

3. Market-specific product inclusion
- Do not include products in a country/city feed unless they are actually purchasable in that market.
- Example: if a cake is available in Lebanon but not Dubai, include it in the Lebanon feed and exclude it from the UAE/Dubai feed.
- Product feed availability must match the customer-facing product page availability.
- Product feed price and currency must match the customer-facing product page for that market.

4. Product URLs
- Feed links should point to the correct localized/city product page.
Examples:
  https://www.presentail.com/en-lb/beirut/products/{slug}
  https://www.presentail.com/en-ae/dubai/products/{slug}
- Make sure these URLs are canonical, crawlable, and not blocked by robots.txt.
- Product pages must return 200 status for active products.

5. Images
- Use the main product image as g:image_link.
- Use absolute HTTPS URLs only.
- If additional product images exist, include g:additional_image_link.
- Do not include broken, relative, or protected image URLs.
- Ensure images are crawlable by Google.

6. Structured data on product pages
Add JSON-LD Product structured data to every product detail page.
The structured data should include:
- @context = https://schema.org/
- @type = Product
- name
- image
- description
- sku/product id
- brand = Presentail
- offers:
  - @type = Offer
  - url
  - priceCurrency
  - price
  - availability using schema.org values:
    InStock / OutOfStock
  - itemCondition = NewCondition

Important:
- Structured data price, currency, availability, and URL must exactly match the visible page and the Merchant Center feed.
- Generate structured data dynamically based on selected country/city/currency.

7. Shipping, returns, and policy pages
Ensure the following pages exist and are linked in the footer:
- /shipping-policy
- /return-policy
- /contact
- /terms
- /privacy-policy

These pages should be crawlable and not hidden behind login.

8. Robots and sitemap
- Make sure robots.txt does not block product pages, feed URLs, images, or policy pages.
- Add product pages to sitemap.xml.
- Include localized/city product URLs in sitemap where relevant.
- Make sure Merchant Center feed URLs are accessible without authentication.

9. Feed validation and safety
- Escape XML characters correctly.
- Strip HTML from descriptions or convert safely.
- Exclude products missing required fields:
  title, description, link, image, price, currency, availability.
- Add logging for products excluded from the feed and why.
- Add a simple admin/debug endpoint or internal log showing:
  total products considered,
  total included,
  total excluded,
  exclusion reasons.

10. Future-ready architecture
- Keep the feed generation logic reusable so we can later support:
  Google Content API / Merchant API
  supplemental feeds
  promotions
  product reviews
  city-level feeds
  custom labels for ad optimization

Please implement this carefully and test:
- XML validates correctly.
- Feed opens publicly in browser.
- Product URLs open correctly.
- Product images open publicly.
- Prices/currency match frontend.
- Products unavailable in a city are excluded from that city’s feed.
- JSON-LD Product structured data appears on product pages.
