We need to fix an authorization bug on Presentail.com.

Context:
Presentail.com is an e-commerce website where users buy flowers, plants, gifts, and checkout online. We use Clerk for user authentication, and Clerk itself is working correctly.

Current bug:
When a Presentail admin logs into the storefront, they are blocked from shopping and see an unauthorized page that says:

“You’re signed in elsewhere.
This account isn’t a Presentail shopper. Switch to a customer account to access your orders and profile.”

This currently prevents admin users from browsing as customers, adding items to cart, checking out, and accessing normal shopper flows.

Goal:
Admins should be able to shop and checkout on Presentail just like normal customers, while still keeping their admin privileges.

Please inspect the codebase and fix the authorization logic so that:
1. Customer users can continue shopping exactly as they do now.
2. Admin users can also access the storefront, cart, checkout, profile, and order-related pages.
3. Admin users must not lose admin access or be converted into regular customers.
4. Any routes that should be admin-only, such as dashboards, product management, order management, or internal tools, must remain admin-only.
5. Any routes that should be shopper-accessible should allow both `customer` and `admin` roles.
6. If the system currently requires a “shopper”, “customer profile”, or similar database record before checkout/profile access, create or associate one for admin users automatically without changing their Clerk role.
7. Preserve all existing Clerk authentication behavior.

Please look for:
- Middleware or route guards that redirect non-customer users to `/unauthorized`
- Logic that checks something like `role === "customer"` and replace it with a safer helper such as `canShop(user)` or `hasShopperAccess(user)`
- Clerk metadata checks, for example `publicMetadata.role`, `privateMetadata.role`, organization role, or similar
- Profile/order/checkout code that assumes admins are not shoppers
- Any database logic that requires a customer profile before checkout

Suggested implementation:
Create a centralized authorization helper so the logic is not duplicated. For example:

- `isAdmin(user)`
- `isCustomer(user)`
- `canShop(user)` should return true for both customers and admins
- `canAccessAdmin(user)` should return true only for admins

Then update storefront/customer routes to use `canShop()` instead of only allowing customers.

Acceptance criteria:
- A normal customer can browse, add to cart, checkout, and view orders.
- An admin can browse, add to cart, checkout, and view their own shopper/order profile.
- An admin can still access the admin dashboard.
- A non-authenticated user is still handled according to the existing sign-in behavior.
- A logged-in user with no valid role still sees the correct unauthorized state.
- Admin-only routes are not exposed to customers.
- No existing checkout/payment/order behavior is broken.

Please make the smallest safe change possible, add comments where the authorization logic is changed, and include a short summary of what files were updated and how to test the fix.
