Fix the app’s currency display logic.

Current issue:
The app asks for location permission, but currency still does not update correctly based on the user’s country.

Required behavior:
1. Detect the user’s country reliably.
2. Show prices in the currency assigned to that country.
3. If the detected country does not have a dedicated currency configured in our store/app pricing system, fall back to USD.
4. Do not depend only on browser GPS permission, because users may deny it or it may fail.
5. Use a fallback detection method:
   - First: use existing saved user country if available.
   - Second: use IP-based country detection.
   - Third: use browser locale only as a weak fallback.
   - Final fallback: USD.

Implementation requirements:
- Create a clear country-to-currency mapping.
- Create a list of currencies actually supported by the store.
- Only display a detected currency if it exists in the supported currency list.
- Otherwise display USD.
- Make this logic reusable in one function, for example:

getCurrencyForUser({
  savedCountry,
  gpsCountry,
  ipCountry,
  browserLocale
})

Expected logic:
- Determine country in this priority order:
  savedCountry → gpsCountry → ipCountry → browserLocale country → null
- Convert country to currency.
- Check if that currency is supported by the store.
- If supported, return it.
- If not supported, return "USD".

Also:
- Add logs or debug output showing:
  detected country
  detection source
  mapped currency
  final currency used
- Remove any broken logic that assumes location permission automatically gives a country.
- Do not show incorrect local currency if it is not supported by the store.
- Test with examples:
  Lebanon → LBP if supported, otherwise USD
  UAE → AED if supported, otherwise USD
  France → EUR if supported, otherwise USD
  Unknown country → USD
  Location permission denied → use IP country, otherwise USD

Make the smallest safe code changes needed and explain what files were changed.
