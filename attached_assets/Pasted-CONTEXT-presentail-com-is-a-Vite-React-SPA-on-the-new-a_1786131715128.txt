CONTEXT

presentail.com is a Vite + React SPA on the new architecture (routes like
/en-lb/beirut/..., /en-ae/dubai/..., /en-ae/abu-dhabi/..., /en-cy/nicosia/...).
The old WordPress site's URLs (/lebanon/..., /dubai/..., /abudhabi/...,
/cyprus/..., /tips-and-tricks/..., etc.) are still indexed in Google and are
handled by a legacy-URL redirect layer that 301s them into the new site.
I don't know exactly where this redirect logic lives in the codebase (a
_redirects file, a vercel.json/netlify.toml rewrites block, a middleware/edge
function, or a hardcoded routing table) — locating it is the first step below.

Two separate, confirmed bugs need fixing. Both were found by curling the live
site on 2026-08-07 (no cache, no JS execution needed — these are plain HTTP
redirect responses).

BUG 1: Every legacy Abu Dhabi URL redirects to Dubai instead of Abu Dhabi

`https://presentail.com/en-ae/abu-dhabi` is a real, fully-built page on the
new site — it loads correctly with its own title ("Flower & Gift Delivery in
Abu Dhabi | Presentail") and its own canonical tag. But every legacy
`/abudhabi/*` URL currently redirects to the DUBAI equivalent instead of the
Abu Dhabi equivalent:

  curl -I https://presentail.com/abudhabi/
  → 301 → /en-ae/dubai                              (should be /en-ae/abu-dhabi)

  curl -I https://presentail.com/abudhabi/shop/
  → 301 → /en-ae/dubai                              (should be /en-ae/abu-dhabi/shop)

  curl -I https://presentail.com/abudhabi/categories/
  → 301 → /en-ae/dubai                              (should be /en-ae/abu-dhabi or its shop/category hub)

  curl -I https://presentail.com/abudhabi/product-category/flowers/
  → 301 → /en-ae/dubai/category/hand-bouquets       (should be /en-ae/abu-dhabi/category/hand-bouquets)

  curl -I https://presentail.com/abudhabi/product-category/valentines-day-gifts/
  → 301 → /en-ae/dubai/shop                         (should be an Abu Dhabi category — see BUG 2's sibling task below)

  curl -I https://presentail.com/abudhabi/product-category/balloons-bundles/
  → 301 → /en-ae/dubai/shop                         (same — should target Abu Dhabi, not Dubai)

  curl -I https://presentail.com/abudhabi/product-category/foil-helium-balloons/
  → 301 → /en-ae/dubai/shop                         (same — should target Abu Dhabi, not Dubai)

  curl -I https://presentail.com/abudhabi/product/happy-birthday-chocolate-box/
  → 301 → /en-ae/dubai/product/happy-birthday-chocolate-box
    (should be /en-ae/abu-dhabi/product/happy-birthday-chocolate-box —
    ONLY if that product actually exists in the Abu Dhabi catalog; if it
    doesn't, redirecting to Abu Dhabi's /shop is better than sending it to
    Dubai)

This looks like it's caused by ONE wrong constant/mapping entry (the legacy
city segment "abudhabi" mapping to the string "dubai" instead of "abu-dhabi"
somewhere in the redirect table), not dozens of individual mistakes — find
that single source of truth and fix it there rather than patching each rule
individually. Every `/abudhabi/*` path should preserve its Abu Dhabi
destination throughout the redirect chain — same relative structure as the
already-correct `/dubai/*` → `/en-ae/dubai/*` and `/cyprus/*` → `/en-cy/nicosia/*`
mappings.

BUG 2: Two real, currently-indexed URLs 404 via a self-redirect loop

These aren't suboptimal redirects — they're dead ends right now for anyone who
clicks through from Google:

  curl -I https://presentail.com/birthday-gift-ideas-lebanon/
  → 301 → /birthday-gift-ideas-lebanon   (redirects to itself, minus trailing slash)
  → that URL renders "404 Not Found – Presentail"

  curl -I https://presentail.com/tips-and-tricks/page/2/
  → 301 → /tips-and-tricks/page/2        (redirects to itself, minus trailing slash)
  → that URL renders "404 Not Found – Presentail"

I checked and this second one isn't a one-off — the ENTIRE blog pagination
range self-redirects into 404 the same way:

  /tips-and-tricks/          → 301 → /tips-and-tricks          → 404
  /tips-and-tricks/page/1/   → 301 → /tips-and-tricks/page/1   → 404
  /tips-and-tricks/page/2/   → 301 → /tips-and-tricks/page/2   → 404
  /tips-and-tricks/page/3/   → 301 → /tips-and-tricks/page/3   → 404
  /tips-and-tricks/page/4/   → 301 → /tips-and-tricks/page/4   → 404
  /tips-and-tricks/page/5/   → 301 → /tips-and-tricks/page/5   → 404

Confirmed real destinations to redirect these to instead:

  https://presentail.com/en-lb/beirut/occasion/birthday
    → real page, loads correctly, title "Birthday Flowers & Gifts in Beirut |
    Presentail" — this is where /birthday-gift-ideas-lebanon/ should redirect.

  https://presentail.com/en-lb/beirut/blog
    → real page, loads correctly, title "The Atelier Journal | Presentail" —
    this is where the entire /tips-and-tricks/* pagination range should
    redirect (the old blog archive doesn't need to map to specific paginated
    URLs on the new blog; redirecting the whole family to the blog index is
    fine — check whether the new blog supports its own pagination and only
    bother mapping page numbers 1:1 if that's trivial, otherwise the index is
    a perfectly good landing page for old blog-archive traffic).
