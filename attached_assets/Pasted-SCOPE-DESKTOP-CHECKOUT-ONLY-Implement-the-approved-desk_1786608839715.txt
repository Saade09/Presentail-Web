SCOPE: DESKTOP CHECKOUT ONLY

Implement the approved desktop checkout redesign shown in the generated mockup.

This task is intentionally limited to desktop. Do not change the mobile checkout experience as part of this task. Mobile behavior/design will be handled separately.

OBJECTIVE

Shorten and clarify the desktop Delivery Details step by implementing exactly these four approved changes:

1. Stop asking customers to choose delivery twice.
2. Make the selected delivery promise concrete.
3. Apply the improved Order Summary hierarchy.
4. Compress Sender Details.

Do not add the later address-flow ideas or mobile recommendations to this task.

CURRENT PROBLEM

The desktop checkout currently repeats delivery selection after the customer already chose a delivery method in the cart. “Express Delivery” is shown without a concrete arrival deadline. The Order Summary uses generic financial labels and contains an irrelevant free-delivery promotion. Sender Details takes more vertical space than needed.

The approved desktop design treats delivery as a confirmation with a Change action, carries the clearer pricing hierarchy from cart into checkout, and reduces Sender Details to a compact identity block.

1. REMOVE DUPLICATE DELIVERY SELECTION

Remove the entire desktop “DELIVERY TIME” section from the left column, including:

• Express Delivery option card
• Schedule option card
• Delivery date chips
• Delivery time chips
• Selected-delivery footer within that section

Do not replace it with another selector in the left column.

The customer’s valid delivery choice from cart should carry into checkout.

Delivery can be changed only through the “Change” action in the right-side delivery confirmation panel.

When “Change” is clicked:

• Open or route to the existing delivery-selection experience.
• Preserve all recipient and sender form data.
• Return the customer to the checkout with the revised delivery choice.
• Update the delivery promise, pricing rows, total, and CTA together.
• Do not require the customer to re-enter checkout details.

7. PRICING AND STATE CONSISTENCY

Use the existing server-authoritative cart/checkout quote as the source of truth for:

• Items subtotal/count
• Standard delivery charge or free status
• Express upgrade presence and amount
• Promo/gift-card changes
• Total
• Delivery type
• Delivery promise/window
• CTA total

Update these values atomically after:

• Delivery changes
• Cart edit
• Promo/gift card applied or removed
• Address/district change if it affects the quote
• Quote expiration/revalidation
• Returning from cart
• Restoring the checkout session

Never show contradictory states such as:

• Express promise with no Express upgrade row when it should be charged.
• Standard promise while Express upgrade remains.
• Summary total differing from CTA.
• Old arrival deadline with new pricing.
• Stale promo value after a delivery change.

If recalculation is required:

• Preserve existing form data.
• Keep the previous stable state or show a restrained loading state.
• Do not flash zeros.
• Do not clear recipient/sender fields after a network or pricing error.
