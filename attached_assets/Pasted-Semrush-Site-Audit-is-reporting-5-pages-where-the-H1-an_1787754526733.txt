Semrush Site Audit is reporting **5 pages where the H1 and HTML `<title>` tag are identical**.

Affected examples include:

* `/en-lb/chouf/product/summer-daisy-garden`
* `/en-lb/jezzine/product/my-protector`
* `/en/blog/flower-shops-in-lebanon`
* `/fr/blog/corporate-gifting-lebanon`
* `/fr/blog/flower-shops-in-lebanon`

This task must be treated as a **systemic SEO architecture issue**, not as five individual content edits.

## Core Requirement

Please identify **why our page-generation system is allowing the H1 and title tag to be identical**, and implement a permanent solution so future:

* Products
* Blog posts
* Categories
* Cities
* Brands
* Occasions
* Corporate pages
* Landing pages
* Localized EN / FR / AR pages

do not accidentally generate identical H1 and title tags unless there is a deliberate SEO reason.

Do **not** simply edit these five pages manually and close the issue.

---

# 1. Diagnose the Root Cause

Inspect how Presentail currently generates:

* `<title>`
* `<h1>`
* SEO title
* Page/display title
* Product name
* Blog title
* Location name
* Meta description

Determine whether the system currently does something like:

`title tag = page title`

and

`H1 = page title`

If both are being populated from the same field with no SEO-specific logic, this is likely the architectural problem.

Also check whether the issue originates from:

* Database schema
* CMS/content model
* SEO metadata generator
* Product-page template
* Blog-page template
* Route metadata
* Translation/localization layer
* Fallback logic

Report the exact root cause before changing anything.

---

# 2. Establish Separate SEO Responsibilities

The application should conceptually support two different values:

### Page H1

Primarily written for the user and visible on the page.

### SEO Title

Primarily written for search results and placed inside `<title>`.

These values may be related, but they should not automatically be identical.

Example:

**H1**
`Summer Daisy Garden`

**SEO title**
`Summer Daisy Garden Flower Arrangement in Chouf | Presentail`

Another example:

**H1**
`Flower Shops in Lebanon: A Complete Guide to Ordering Online`

**SEO title**
`Best Flower Shops in Lebanon & Online Delivery | Presentail`

The SEO title can add:

* Location
* Product/category intent
* Delivery intent
* Occasion
* Brand
* Presentail

without making the visible H1 unnaturally long.

---

# 3. Implement Proper Metadata Fields

Review our data model.

Where appropriate, support dedicated fields such as:

* `name`
* `h1`
* `seoTitle`
* `metaDescription`

Do not necessarily add all four fields everywhere if our existing architecture already supports something equivalent.

The goal is to ensure our SEO layer can generate a title independently from the display/H1 text.

Existing content must remain backward compatible.

---

# 4. Add Intelligent Fallback Logic

We should not require someone to manually write an SEO title for thousands of Presentail pages.

Create sensible template-based fallback generation.

For example:

### Product Page

If custom SEO title exists:

`seoTitle`

Otherwise generate something similar to:

`{Product Name} — {City} | Presentail`

or, when natural:

`{Product Name} Delivery in {City} | Presentail`

H1 remains:

`{Product Name}`

---

### Category Page

H1:

`Balloon Delivery in Beirut`

SEO title:

`Balloon Delivery Beirut | Same-Day Balloons | Presentail`

---

### Brand Page

H1:

`{Brand Name}`

SEO title:

`Shop {Brand Name} in {City} | Presentail`

---

### Occasion Page

H1:

`Birthday Flowers & Gifts`

SEO title:

`Birthday Flowers & Gift Delivery in {City} | Presentail`

---

### Blog Article

The article headline should remain editorial.

H1:

`Flower Shops in Lebanon: A Complete Guide to Ordering Online`

SEO title can be a shorter/search-focused variant such as:

`Flower Shops in Lebanon & Online Delivery | Presentail`

Do not mechanically generate poor titles.

For blog content, continue supporting an explicitly authored SEO title when available.

---

# 5. Handle Localization Properly

This needs to work independently for:

* English
* French
* Arabic

Do not create English SEO-title templates and mechanically concatenate them onto French or Arabic content.

The SEO-title generator should support locale-specific patterns.

For example, French syntax may differ from English.

Arabic titles must:

* use natural Arabic
* retain correct RTL rendering
* avoid awkward English ordering
* avoid unnecessary English text except the Presentail brand

---

After the system-level solution exists, use it to fix the currently reported pages.

Do not hardcode exceptions for these URLs.

Review the generated titles individually so they remain natural.

Particularly:

### Summer Daisy Garden — Chouf

H1 can remain:

`Summer Daisy Garden`

SEO title should include useful search context/location.

H1 can remain:

`My Protector`

SEO title should add product/location context without keyword stuffing.

Create a more concise search-focused SEO title.

---

### French Corporate Gifting Article

Create a distinct French SEO title.

Keep the editorial H1.

Create a distinct, natural French SEO title.

# 7. Add Automatic SEO Guardrails

This is especially important.

Add validation so we stop discovering the same issue through Semrush later.

When generating/rendering SEO metadata, detect cases where:

`normalized(H1) === normalized(SEO title)`

Normalization should safely account for things like:

* Case
* Excess spaces
* Basic punctuation
* Brand suffix such as `| Presentail`

We should flag suspicious duplicates during development/content creation.

Depending on the current architecture, implement the most appropriate method:

* Admin warning
* Build-time check
* Automated SEO audit
* Development console warning
* CI test
* Content validation

Prefer something that can run across the entire database/site.

---

# 8. Build a Site-Wide SEO Validation Utility

Create or extend a reusable SEO validation layer capable of checking pages for common metadata problems.

At minimum detect:

* Missing title
* Missing H1
* Duplicate H1/title
* Multiple H1s
* Empty meta description
* Duplicate title tags
* Duplicate meta descriptions
* Excessively long title
* Excessively short title
* Incorrect canonical
* Missing canonical
* Missing hreflang where expected

We should eventually be able to run this against all generated routes before Semrush finds the problems.

Do not necessarily build a large UI for this task.

A reusable script/service/test is sufficient for V1.

---

# 9. Preserve SEO Quality

Do not blindly make titles different by adding meaningless text.

For example, this is **not** an acceptable fix:

H1:
`Summer Daisy Garden`

Title:
`Summer Daisy Garden | Presentail`

if our validator simply ignores the Presentail suffix and the meaningful search intent remains identical.

The title should genuinely provide additional SERP context.

Similarly, do not create titles like:

`Buy Summer Daisy Garden Best Cheap Fast Flower Delivery Chouf Lebanon`

Avoid keyword stuffing.

---

# 10. Title Length

Aim for concise SERP titles, generally around **50–60 characters where practical**.

This is a guideline, not a hard truncation rule.

Do not cut words arbitrarily just to meet a character limit.

---

# 11. Existing Custom SEO Metadata

If a page already has a manually authored SEO title, preserve it unless it is invalid.

Priority should generally be:

1. Explicit SEO title
2. Template-generated SEO title
3. Safe fallback

Do not overwrite manually optimized metadata every deployment.

---

# 12. Do Not Break Existing Functionality

Do not alter:

* URLs
* Slugs
* Product names
* Product availability
* Product pricing
* Delivery logic
* Visible page design
* Structured data unnecessarily
* Canonicals
* Existing rankings
* Existing localized content

Any metadata change must remain server-rendered and visible to crawlers.

# Definition of Done

This task is complete only when:

1. The root cause of duplicate H1/title generation is identified.
2. H1 and SEO title are conceptually separated in the architecture.
3. A reusable SEO-title generation/fallback system exists.
4. EN, FR and AR are handled correctly.
5. The current five Semrush errors are resolved.
6. Existing manually optimized SEO titles are preserved.
7. Automated validation prevents recurrence.
8. Representative templates are tested.
9. No page design/functionality is broken.

When finished, report back with:

### Root Cause

Why Presentail was generating identical H1 and title tags.

### Permanent Fix

What architecture/template/data-model changes were made.

### Current Pages Fixed

What the resulting H1 and SEO title are for the five affected pages.

### Guardrail Added

How future duplicate H1/title issues will be detected automatically.

### Validation

How many routes/pages were checked after the change.
