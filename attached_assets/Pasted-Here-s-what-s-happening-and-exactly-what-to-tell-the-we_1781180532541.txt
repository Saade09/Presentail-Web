Here's what's happening and exactly what to tell the website.

Your OS already exposes a storefront products endpoint that's separate from the internal dashboard one. The website just needs to call it correctly. Tell whoever built the website to check these things:

1. The endpoint and how to authenticate
URL: GET https://os.presentail.com/api/products
API key: send it as a header x-api-key: pk_live_... (it also accepts Authorization: Bearer pk_live_... or ?apiKey=pk_live_...).
The key must start with pk_live_. If the key is missing or wrong, the request silently falls through to the internal login-protected route and comes back as 401 / unauthorized — which a website often shows as "no products." So step one: confirm the key is valid and being sent on every request.
2. Read the right field in the response
The response is not a bare array. It looks like this:

{
  "products": [ ... ],
  "total": 541,
  "page": 1,
  "pageSize": 25,
  "totalPages": 22
}

A very common cause of "nothing shows" is the website reading response.data or expecting a top-level array. It must read response.products. Also note the fields are camelCase (priceAed, inStock, images, deliverableCities), not the snake_case names from your dashboard.

3. Don't over-filter
The endpoint accepts optional filters, and any of these will shrink the list to empty if they don't match:

inStockOnly — defaults to true, so only products with status Available come back (you have 541, so that's fine).
cityId — expects a city slug (e.g. beirut, dubai), not a numeric ID. A wrong value returns zero products.
countryCode — a 2-letter code (e.g. lb, ae). A wrong value returns zero.
page / pageSize (max 100, default 25).
Best test: have them call GET /api/products?inStockOnly=true with just the API key and no city/country filters. If products come back, the problem is their filters (likely passing a city ID instead of a city slug, or a country/city you don't deliver to). If still empty, the problem is the API key or the path.

4. Webhook vs. fetching are separate
The webhook you connected only notifies the site when catalog attributes change — it doesn't deliver the product list. To show products, the site still has to fetch GET /api/products as above. If they were relying on the webhook to push products, that's the core misunderstanding.
