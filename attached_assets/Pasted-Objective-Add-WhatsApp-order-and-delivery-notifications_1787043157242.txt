Objective
Add WhatsApp order and delivery notifications to the checkout. The option must be enabled (checked) by default for the sender.

UX placement and copy
- Place the option in the Sender Details card.
- Position it directly below the sender Phone Number field and above “Send this gift anonymously.”
- Use the existing checkbox component and Presentail checkout styling.
- Default state: checked.
- Label: “Get order updates on WhatsApp”
- Helper text: “We’ll send order and delivery updates to this number. Opt out anytime.”
- Show a small WhatsApp icon beside the label.
- Keep the anonymous-gift control independent.

Functional requirements
- Use the sender’s entered phone number; do not introduce a second phone-number field.
- If checked when checkout is submitted, save the WhatsApp notification preference against the order and sender phone number.
- If the customer unchecks it, do not send any WhatsApp notifications for that order.
- Preserve the selection while navigating between Delivery Details and Payment and after recoverable validation errors.
- Do not message the recipient through this setting.
- This setting covers transactional updates only; do not enroll the customer in marketing messages.

Notification coverage
- Order confirmed
- Order dispatched / out for delivery
- Order delivered
- Delivery issue or material delay

Backend / integration
- Normalize and validate the sender number in E.164 format using the selected country code.
- Pass the preference and normalized number to the order backend.
- Trigger the approved WhatsApp utility templates only when the saved preference is enabled.
- Make message sending idempotent so retries do not produce duplicate customer notifications.
- Log send status and provider message ID for support/debugging.
- WhatsApp delivery failures must not block checkout or alter the order status.

Analytics
Track:
- whatsapp_updates_default_shown
- whatsapp_updates_disabled
- checkout_completed_with_whatsapp_updates
Include checkout/session ID and final enabled state; do not include the raw phone number in analytics.

Acceptance criteria
1. The WhatsApp row appears below Sender Phone Number and matches the supplied mockup/layout.
2. The checkbox is checked by default on a new checkout.
3. Customers can uncheck and re-check it using mouse and keyboard.
4. The control has an accessible label, visible focus state, and correct checked state for screen readers.
5. The selected state persists through payment-step navigation and validation errors.
6. The final preference is stored with the order.
7. Checked orders receive the configured transactional WhatsApp updates at the sender number.
8. Unchecked orders receive no WhatsApp messages.
9. The anonymous-gift option continues to work independently.
10. No WhatsApp failure prevents checkout completion.
11. Responsive layout is verified on desktop and mobile.
12. Automated tests cover default state, opt-out, persistence, backend storage, and notification gating.

QA scenarios
- Guest checkout with a valid Lebanese number.
- Logged-in checkout.
- Customer unchecks before payment.
- Customer returns from Payment to Delivery Details.
- Validation error after changing the setting.
- Invalid or non-WhatsApp-capable number.
- Provider timeout/retry.
- Anonymous gift enabled and disabled.
- Desktop and mobile breakpoints.
