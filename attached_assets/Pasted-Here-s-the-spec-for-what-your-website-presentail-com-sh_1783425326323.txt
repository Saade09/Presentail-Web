Here's the spec for what your website (presentail.com) should push to the OS for analytics. This is all based on the ingestion endpoint that already exists.

Where to send it
POST /api/web-events on the OS server, authenticated with your workspace API key (pk_live_…) via x-api-key header (or Authorization: Bearer). You can send one event at a time or batch up to 500 per request as { "events": [...] }.

Event types the dashboards actually use
These are the ones that power the Cart & Checkout and Marketing analytics pages — the most important ones to get right:

Event type	When to fire it	Extra fields that matter
page_view	Every page load	path, referrer, UTM fields
product_view	Product detail page opened	productRef, brand, category, occasion
add_to_cart	Item added to cart	value (cart total), currency — can be the customer's own currency, OS converts to USD
checkout_step	Customer reaches/advances checkout	properties.city, properties.deliverySlot, properties.deliveryFee (0 vs non-zero is what matters)
payment_started	Payment initiated	—
payment_completed	Order confirmed	value, currency
payment_failed	Payment declined/errored	—
promo_applied / promo_failed	Coupon accepted / rejected	properties.code
search / search_no_result	Search performed	searchQuery, resultCount
Also recommended (accepted, useful later): country_selected, city_selected, category_view, occasion_view, remove_from_cart.

The checkout funnel is computed as: sessions → product_view → (checkout_step or payment_started) → payment_completed. If any of those are missing, the funnel and abandonment cards show a "waiting for website events" state.

Fields to include on every event
sessionId — critical. All funnel/conversion math groups by session. Generate one per browsing session and attach it to every event.
visitorId — a persistent (e.g. localStorage) ID for repeat-visitor analysis.
occurredAt — ISO timestamp (defaults to server receive time if omitted).
Attribution: utmSource, utmMedium, utmCampaign, utmTerm, utmContent, referrer, trafficSource — these drive the by-source/marketing breakdowns.
Context: deviceType, language, country, city, url, path.
Everything except type is optional, and unknown extra keys are preserved automatically (they land in a properties bag), so the website is never blocked by validation — but sparse events mean sparse dashboards.

Two things that trip people up
add_to_cart value + currency: send the cart total in whatever currency the customer sees, with the currency code — OS converts to USD using your stored FX rates. Without it, the free-delivery-bar and average-cart cards stay empty.
Session consistency: the same sessionId must appear on the product_view, checkout_step, and payment_completed events of one visit, or the funnel undercounts conversions.
Note that country/city/channel filters on the analytics pages don't apply to web-event cards (only date range + brand do), so don't worry about matching those to order data exactly.
