Update the Plants category page so products are split into two sections:



1. Indoor Plants

2. Outdoor Plants



Requirements:



- Keep the existing Plants category page, filters, sidebar, sorting, product cards, pricing, links, and responsive layout unchanged.

- Replace the single product grid with two separate product groups.

- Add a clear section title above each grid:

  - “Indoor Plants”

  - “Outdoor Plants”

- Each section must use the same product card design and grid spacing already used on the page.

- Do not create new product categories or manually change the product data in OS unless required.

- Products must still be fetched from OS using the current integration.



AI classification:



- Use AI to classify every product in the Plants category as either indoor or outdoor.

- The AI must analyze:

  - Product name

  - Product image

  - Product description, tags, or existing metadata when available

- The classification result must be exactly one of:

  - `indoor`

  - `outdoor`

- Examples:

  - Orchids, bonsai, snake plants, money trees, guzmania, and small decorative potted plants will usually be indoor.

  - Palms, larger shrubs, garden plants, and plants intended for balconies or outdoor spaces will usually be outdoor.

- Do not rely only on the product name. Analyze the image and available product data together.



Performance and storage:



- Do not call the AI every time the category page loads.

- Classify each product once, then save the result in the website database using a field such as:

  - `plant_environment_type`

- Reuse the saved classification on future page loads.

- Run AI classification only when:

  - A plant product has no saved classification

  - Its name, main image, or description has changed

  - An admin manually requests reclassification

- Process classifications in the backend, not during frontend rendering.

- The page must still load normally if the AI service is unavailable.



Fallback logic:



- If AI classification fails, use existing tags, descriptions, product attributes, or a conservative keyword-based fallback.

- If the product still cannot be classified confidently, place it under “Indoor Plants” temporarily and mark it internally as needing review.

- Never hide a product because classification failed.



Admin controls:



- Add an editable plant type field in the relevant product management area:

  - Indoor

  - Outdoor

- A manual admin selection must override the AI classification.

- Add a “Reclassify with AI” action for individual products.

- Add a bulk action to classify or reclassify all products in the Plants category.

- Store whether the current value was assigned by:

  - AI

  - Admin

  - Fallback



Frontend behavior:



- Show “Indoor Plants” first, followed by “Outdoor Plants.”

- Only show a section if it contains at least one product.

- Products must remain compatible with existing sorting and price filters.

- When the customer changes the sorting option, sort the products inside each section independently.

- Filters must update both sections.

- Preserve the current three-column desktop grid and existing mobile/tablet behavior.

- Do not duplicate products between sections.

- Do not change other categories such as Flowers, Cakes, Chocolates, Bundles, or Gift Baskets.



Implementation checks:



- Confirm where plant products are currently fetched from OS.

- Confirm how product images and metadata are stored.

- Reuse the existing product query and product-card component.

- Do not build a second unrelated product-fetching system.

- Add database migration support for the new classification fields.

- Handle existing products and newly imported products.

- Test desktop, tablet, and mobile layouts.

- Verify that all current plant products appear exactly once under one of the two titles.



Automatic re-analysis for new products:



- The system must automatically detect when new products are added to the Plants category from OS.

- Newly added products should automatically be queued for AI classification before being displayed on the page.

- Existing classified products must not be reprocessed unnecessarily.

- The system should periodically compare the current Plants catalog with the stored classifications and identify:

  - New products without a classification.

  - Products whose primary image, name, or description has changed.

- Only those products should be sent back through the AI for classification.

- Keep all existing classifications intact unless a product has changed or an admin explicitly requests reclassification.

- This process should run automatically in the background and should never slow down page loads.

- If a new product has not yet been classified, temporarily place it under "Indoor Plants" while marking it as "Pending AI Classification." Once the AI completes the analysis, automatically move it to the correct section without requiring code changes.

- The implementation should be fully self-maintaining so that future plant products imported from OS are automatically analyzed and categorized without any developer intervention.
