## Objective

Fix the desktop cart-page checkout sidebar so it is visually aligned when the page first loads and remains usable as the customer scrolls through the card-message and “Complete your gift” sections.

Page: https://presentail.com/en-lb/beirut/cart

## Problem

On initial load, the right column currently begins noticeably lower than the left column, leaving an unexplained empty area above “Delivery Summary.” This makes the layout feel unfinished and delays access to important checkout information.

While scrolling, the customer should continue seeing the delivery details, order total, promo-code control, and checkout CTA without the sidebar overlapping the site header or extending outside the usable viewport.

## Required behavior

### 1. Initial desktop state

- Remove the artificial top gap above the right-hand sidebar.
- Align the top edge of the “Delivery Summary” card with the top of the “Cart (2)” heading in the left column.
- Treat “Delivery Summary” and “Order Summary” as one sidebar unit.
- Preserve the current spacing between both cards.
- Do not add a promotional banner, trust badge, placeholder, or other content merely to fill the empty space.
- Preserve all existing sidebar content, styling, shadows, widths, and functionality.
- The initial page load must not visibly jump while the sticky position is calculated.

### 2. Desktop scrolled state

- Make the sidebar wrapper sticky, not fixed.
- When the sticky state is active, position the top of the sidebar 24px below the bottom edge of the sticky site header.
- Keep both summary cards moving together when the full unit fits within the available viewport height.
- Keep the checkout button completely visible whenever viewport height allows.
- The sticky sidebar must stop at the bottom boundary of its containing cart section and must never overlap the footer or subsequent page content.
- Scrolling the main page must remain natural; do not create a nested scrollbar inside the sidebar.

### 3. Short desktop viewport fallback

- Calculate whether the complete sidebar height can fit within the viewport after accounting for the sticky header, 24px top spacing, and safe bottom spacing.
- If the complete Delivery + Order Summary unit cannot fit, do not trap or hide content.
- Use the least disruptive fallback: allow Delivery Summary to remain in normal document flow and keep only Order Summary sticky, or disable stickiness for the combined unit if that integrates more safely with the existing component structure.
- The user must always be able to reach every summary control and the checkout button through normal page scrolling.

### 4. Tablet and mobile

- Use the project’s existing responsive breakpoint; do not introduce an arbitrary breakpoint if one already exists.
- Below the desktop/two-column breakpoint, disable sidebar stickiness and return both cards to the normal document flow.
- Preserve the intended mobile content order and ensure the checkout CTA does not cover cart content.
- No horizontal overflow.

## Suggested implementation direction

- Apply sticky positioning to the sidebar wrapper rather than independently positioning each card.
- Recommended desktop CSS behavior:
  - `position: sticky`
  - `top: calc(var(--actual-sticky-header-height) + 24px)`
  - `align-self: flex-start`
- Remove any existing top margin, spacer, grid offset, placeholder, or hard-coded value causing the initial empty area.
- Confirm that no ancestor of the sticky element uses `overflow: hidden`, `overflow: auto`, or a transform that unintentionally changes the sticky containing block.
- Reuse the actual header-height token/value if one exists. Do not duplicate a magic pixel value for the header height.
- Keep z-index only as high as required; the sidebar must remain below header overlays, menus, and modals.
- Preserve semantic DOM order and keyboard navigation.

## Acceptance criteria

- On initial desktop load, the top of Delivery Summary aligns with the top of “Cart (2)” within 4px.
- There is no unexplained blank block above the sidebar.
- Delivery Summary and Order Summary retain their current visual spacing and width.
- After scrolling, the sticky sidebar sits 24px below the visible site header within a tolerance of 4px.
- The sidebar does not overlap the header, footer, add-on cards, or left-column content.
- The sidebar stops correctly when its parent container ends.
- The checkout CTA remains clickable and does not shift or flicker.
- Expanding “Add a promo code” does not hide the checkout button permanently or create an inaccessible region.
- Changing the delivery option does not break sticky positioning or cause horizontal movement.
- Adding/removing items and changing quantity do not create layout jumps in the sidebar.
- The solution works when free delivery is unlocked and when a delivery fee is present.
- The layout remains usable at 100%, 125%, and 150% browser zoom.
- No nested sidebar scrollbar is introduced.
- Mobile/tablet layouts remain non-sticky and free of horizontal overflow.
- Existing cart analytics, checkout navigation, promo-code behavior, and delivery-change actions continue working.

## QA matrix

Test at minimum:

- Chrome desktop: 1440×900 and 1280×720
- Safari desktop: 1440×900
- Browser zoom: 100%, 125%, and 150%
- Desktop states:
  - initial page load
  - card-message section
  - “Complete your gift” section
  - promo-code control collapsed and expanded
  - delivery summary changed
  - quantity changed
  - item removed
  - free delivery and paid delivery
- Mobile/tablet at the existing responsive breakpoints

## Definition of done

- Implementation merged and deployed to the relevant staging environment.
- Acceptance criteria pass without regression to the cart or checkout flow.
- Before/after screenshots are added to this task for:
  1. initial desktop state
  2. scrolled desktop state
  3. short-height desktop fallback
  4. mobile state
- Any intentional deviation from the 24px sticky offset or recommended fallback is documented in the task before completion.
