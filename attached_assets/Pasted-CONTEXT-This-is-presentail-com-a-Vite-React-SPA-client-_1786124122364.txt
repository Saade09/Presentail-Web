CONTEXT

This is presentail.com — a Vite + React SPA (client-rendered, bundle names like
index-*.js, vendor-react-*.js). It serves multiple cities (Dubai, Abu Dhabi, etc.)
and multiple occasions (birthday, anniversary, wedding, new-born, sympathy,
valentines-day, ...) under routes like:

  /en-ae/dubai/occasion/{occasion-slug}
  /ar-ae/dubai/occasion/{occasion-slug}
  /fr-ae/dubai/occasion/{occasion-slug}

PROBLEM (verified by curling the live HTML on 2026-08-07)

Every occasion page for a given city currently renders the IDENTICAL title tag,
meta description, and H1 — there is no per-occasion content at all. Example:

  curl https://presentail.com/en-ae/dubai/occasion/birthday
  curl https://presentail.com/en-ae/dubai/occasion/anniversary
  curl https://presentail.com/en-ae/dubai/occasion/wedding
  curl https://presentail.com/en-ae/dubai/occasion/new-born
  curl https://presentail.com/en-ae/dubai/occasion/sympathy
  curl https://presentail.com/en-ae/dubai/occasion/valentines-day

...all six return:
  <title>Gift Delivery in Dubai | Presentail</title>
  <meta name="description" content="Shop the perfect gift for this occasion in
  Dubai, the UAE with same-day delivery from Presentail." />

And the only H1 in the raw DOM is inside a `sr-only` (visually hidden) wrapper,
duplicating the title tag verbatim:
  <div id="root"><h1 class="sr-only">Gift Delivery in Dubai | Presentail</h1>...

This is a duplicate-title/duplicate-meta-description problem across every
occasion × city combination on the site, and it's suppressing search rankings
for occasion-specific keywords (e.g. "birthday gift delivery dubai") because
there is zero on-page signal that a given URL is about that occasion.

Separately: sitemap-en.xml, sitemap-ar.xml, and sitemap-fr.xml list only the
`/occasions` hub page for each city — no individual `/occasion/{slug}` URL is
in any sitemap. The occasion pages are effectively invisible to the sitemap.

Compare this to /lebanon/birthday-gift-ideas-lebanon-2/ (an older page on this
same domain), which DOES render a unique, visible H1, an H2 ("Shop by
Occasion"), and a working FAQ section with real Q&A content. That page is the
right template to generalize from — we are extending a pattern that already
works elsewhere on this site to the newer `/occasion/{slug}` route template,
not inventing something new.
