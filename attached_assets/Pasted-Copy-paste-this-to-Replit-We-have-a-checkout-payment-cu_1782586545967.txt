We have a checkout payment currency bug.

**Issue:**
The customer is shopping in EUR and the checkout order summary correctly shows **€301**, but when Apple Pay opens, Apple Pay shows **$342.00 USD**.

This is wrong and confusing. Apple Pay must charge and display the **same currency and amount** that the customer sees in checkout.

Please investigate and fix the payment currency handling across checkout.

## Expected behavior

If customer checkout currency is:

* EUR → Apple Pay should show EUR amount
* AED → Apple Pay should show AED amount
* USD → Apple Pay should show USD amount
* GBP → Apple Pay should show GBP amount
* SAR/QAR/KWD/etc. → Apple Pay should show the same selected currency, if supported by the payment provider

The amount shown in:

1. Product page
2. Cart
3. Checkout order summary
4. Payment method section
5. Apple Pay / Google Pay / card payment sheet
6. Payment provider request
7. Final order record

must all match.

## What to check

Please audit the full payment flow:

1. **Selected currency source**

   * Confirm where the customer’s selected/display currency is stored.
   * Example: EUR is shown in checkout, so the payment request should also use EUR.

2. **Apple Pay request**

   * Check the Apple Pay / Stripe / payment provider payload.
   * Make sure `currency` is not hardcoded to `USD`.
   * Make sure the amount passed to Apple Pay is the displayed checkout amount converted to the smallest currency unit correctly.

3. **PaymentIntent / checkout session**

   * Confirm the PaymentIntent is created using the selected checkout currency.
   * Example:

     * Displayed checkout: `€301`
     * PaymentIntent currency: `eur`
     * PaymentIntent amount: `30100`

4. **Currency conversion**

   * If the backend uses USD internally, convert before creating the payment request.
   * Do not show EUR in checkout and charge USD in Apple Pay.
   * The customer-facing payment currency must match the checkout currency.

5. **Currency formatting**

   * Ensure currency symbols, decimals, and rounding are correct.
   * Some currencies have 2 decimals, some have 3, and some have 0.
   * Do not assume all currencies behave like USD.

6. **Supported currency fallback**

   * If Apple Pay or the payment provider does not support a selected currency, do not silently switch to USD.
   * Instead, either:

     * show a clear message before payment, or
     * convert the full checkout to the supported fallback currency before the customer reaches payment.

## Also test all other currencies

Please test checkout and Apple Pay/payment sheet behavior for all supported Presentail currencies, especially:

* USD
* EUR
* AED
* GBP
* SAR
* QAR
* KWD
* LBP

For each currency, confirm:

* Product prices show the correct currency
* Cart total shows the correct currency
* Checkout order summary shows the correct currency
* Apple Pay shows the same currency
* Google Pay shows the same currency
* Credit/debit card payment uses the same currency
* Order is saved with the correct currency
* Admin/order confirmation shows the correct charged currency
* Email/WhatsApp confirmation shows the correct currency

## Also test field validation

While testing the payment page, please also review all checkout fields and validation states:

* Required fields should block payment if missing
* Optional fields should not block payment
* Phone number validation should work with country code
* Delivery details should remain saved when moving to payment
* Notes field should save correctly
* Payment button should not activate until the form is valid
* Errors should be clear and visible on mobile
* Changing currency after entering checkout should recalculate the payment amount correctly
* Refreshing the payment page should not reset the currency incorrectly
* Returning from failed Apple Pay should keep the correct currency and amount

## Important acceptance criteria

This bug is fixed only when:

* Checkout shows **€301** and Apple Pay also shows **€301**, not USD.
* No payment method silently changes the customer’s selected currency.
* Backend payment records and frontend order totals match exactly.
* All supported currencies are tested.
* Field validation is tested on mobile checkout.
